## 1. แนวคิด (Concept)

คำว่า **Semantic** แปลว่า **"ความหมาย (Meaning)"** 

ในยุคก่อน HTML5 นักพัฒนาทุกคนใช้ `<div>` ครอบทุกสิ่งทุกอย่างในโลก เช่น `<div class="header">`, `<div class="sidebar">`, `<div class="menu">` ซึ่งสำหรับคอมพิวเตอร์และเบราว์เซอร์แล้ว `<div>` คือกล่องเปล่าที่ไม่มีความหมายใดๆ เลย (Non-semantic Element)

HTML5 จึงเปิดตัว **Semantic Elements** เพื่อบอกบทบาทหน้าที่อย่างชัดเจน:
- `<header>`: ส่วนหัวของหน้า หรือส่วนหัวของบทความ
- `<nav>`: กลุ่มลิงก์สำหรับนำทางหลักของเว็บไซต์
- `<main>`: เนื้อหาหลักอันเป็นเอกลักษณ์ของหน้านั้น (มีได้เพียง 1 อันต่อหน้า)
- `<article>`: เนื้อหาที่สมบูรณ์ในตัวเอง สามารถยกไปเผยแพร่ที่อื่นได้ (เช่น บล็อก, ข่าว, โพสต์โซเชียล)
- `<section>`: ส่วนย่อยของเนื้อหาที่มีหัวข้อ (`<h2>`-`<h6>`) กำกับชัดเจน
- `<aside>`: เนื้อหาเสริมที่ไม่เกี่ยวข้องโดยตรงกับเนื้อหาหลัก (เช่น แถบด้านข้าง, ลิงก์ที่เกี่ยวข้อง, ป้ายโฆษณา)
- `<footer>`: ส่วนท้ายของหน้าเว็บ (เช่น ข้อมูลลิขสิทธิ์, ที่อยู่, ลิงก์นโยบายความเป็นส่วนตัว)

## 2. หลักการเบื้องหลัง (Under the Hood)

1. **Accessibility Landmarks**: เมื่อเบราว์เซอร์ตรวจพบแท็กอย่าง `<main>`, `<nav>`, หรือ `<header>` มันจะแปลงเป็น **Landmarks ใน Accessibility Tree** ผู้พิการทางสายตาสามารถกดคีย์ลัดเพื่อ "ข้ามไปยังเนื้อหาหลัก (Skip to Main Content)" ได้ทันทีโดยไม่ต้องทนฟังเมนูนำทางซ้ำๆ ทุกหน้า
2. **SEO & Content Indexing**: Google Search Algorithm แยกแยะน้ำหนักระหว่างเนื้อหาใน `<article>` และ `<main>` ออกจากเนื้อหาทั่วไปใน `<aside>` และ `<footer>` ทำให้เนื้อหาหลักติดอันดับการค้นหาได้ตรงเป้าหมายยิ่งขึ้น
3. **เมื่อไหร่ควรใช้ `<div>`?**: `<div>` ไม่ใช่สิ่งผิดบาป หน้าที่ของ `<div>` ในยุคปัจจุบันคือ **การเป็น Layout Wrapper เพื่อจุดประสงค์ทาง CSS Styling เท่านั้น** (เช่น การทำ Flexbox/Grid container หรือการจัดกึ่งกลางหน้าจอ)

## 3. ตัวอย่างโค้ด (HTML5)

### ตัวอย่างที่ 1: โครงสร้างระดับมืออาชีพของหน้าพอร์ทัลข่าวไอที

```html filename="news-portal.html"
<!DOCTYPE html>
<html lang="th">
<head>
  <meta charset="UTF-8">
  <title>Scripture News — แหล่งรวมข่าวสารวิศวกรรมซอฟต์แวร์</title>
</head>
<body>
  <!-- 1. ส่วนหัวของเว็บพร้อมเมนูหลัก -->
  <header>
    <div class="logo">Scripture News</div>
    <nav aria-label="เมนูหลัก">
      <ul>
        <li><a href="/">หน้าหลัก</a></li>
        <li><a href="/tech">เทคโนโลยี</a></li>
        <li><a href="/ai">ปัญญาประดิษฐ์</a></li>
      </ul>
    </nav>
  </header>

  <!-- 2. เนื้อหาหลักของหน้านี้ (มีได้เพียง 1 อันต่อหน้า) -->
  <main>
    <!-- บทความเด่นประจำวัน -->
    <article>
      <header>
        <h1>Next.js 16 เปิดตัวพร้อม Turbopack เต็มรูปแบบ</h1>
        <p>เผยแพร่โดย: ทีมบรรณาธิการ</p>
      </header>
      
      <section>
        <h2>ความเร็วในการคอมไพล์ที่เพิ่มขึ้น</h2>
        <p>จากการทดสอบในระดับ Production พบว่าความเร็วในการ HMR สูงขึ้นกว่าเดิม 5 เท่า...</p>
      </section>

      <section>
        <h2>ความเข้ากันได้กับ React 19</h2>
        <p>รองรับ Server Actions และ useActionState ได้อย่างราบรื่น...</p>
      </section>
    </article>
  </main>

  <!-- 3. ส่วนเสริมด้านข้างที่ไม่ใช่เนื้อหาหลัก -->
  <aside aria-label="ข่าวยอดนิยม">
    <h2>ข่าวยอดนิยมสัปดาห์นี้</h2>
    <ul>
      <li><a href="/news/ts-5">TypeScript 5.6 มีอะไรใหม่?</a></li>
    </ul>
  </aside>

  <!-- 4. ส่วนท้ายของหน้า -->
  <footer>
    <p>&copy; 2026 Scripture News. สงวนลิขสิทธิ์ทั้งหมด</p>
  </footer>
</body>
</html>
```

### ตัวอย่างที่ 2: การใช้ `<div>` ร่วมกับ Semantic Tag อย่างถูกหลัก

```html filename="styled-card.html"
<!-- ใช้ <article> ให้ความหมายเชิง Semantic -->
<article class="testimonial-card">
  <h3>ความประทับใจจากลูกค้า</h3>
  <p>&ldquo;ระบบใช้งานง่ายมาก ช่วยให้ทีมประหยัดเวลาได้ถึง 50%&rdquo;</p>
  
  <!-- ใช้ <div> สำหรับทำ Flexbox จัดตำแหน่ง Avatar และชื่อให้อยู่แนวเดียวกันใน CSS -->
  <div class="author-layout-wrapper">
    <img src="/avatars/somchai.jpg" alt="คุณสมชาย ผู้จัดการฝ่ายไอที" width="40" height="40">
    <div class="author-info">
      <strong>สมชาย มั่นคง</strong>
      <span>CTO, บริษัท เทคจำกัด</span>
    </div>
  </div>
</article>
```

## 4. โค้ดที่มักเขียนผิด vs โค้ดที่ถูกต้อง

### ❌ โค้ดที่ผิด: ปรากฏการณ์ "Div Soup"

```html
<!-- ผิด: Div ซ้อน Div โดยไร้ความหมาย Screen Reader และ Googlebot เข้าใจยากมาก -->
<div id="header">
  <div class="nav-links">
    <div class="link"><a href="/">หน้าแรก</a></div>
  </div>
</div>
<div id="content">
  <div class="title">หัวข้อข่าว</div>
</div>
```

### ✅ โค้ดที่ถูกต้อง: ใช้ Semantic Tags ชัดเจน

```html
<!-- ถูกต้อง: สื่อความหมายชัดเจน อ่านง่าย ทั้งคนและ Machine -->
<header>
  <nav aria-label="เมนูหลัก">
    <ul>
      <li><a href="/">หน้าแรก</a></li>
    </ul>
  </nav>
</header>
<main>
  <h1>หัวข้อข่าว</h1>
</main>
```

## 5. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้ Semantic Tags
- ใช้ `<header>`, `<nav>`, `<main>`, `<footer>` วางโครงสร้าง Layout ระดับสากลเสมอ
- ใช้ `<article>` สำหรับเนื้อหาที่สามารถแยกไปอ่านหรือแชร์เดี่ยวๆ ได้
- ใช้ `<section>` เมื่อมีหัวข้อย่อย (`h2`-`h6`) กำกับชัดเจน

### ควรใช้ `<div>`
- เมื่อต้องการกล่องเพื่อจุดประสงค์ทาง CSS เช่น Grid, Flex, Padding, Background Color หรือ Animation โดยไม่มีความหมายเชิงเนื้อหา

## 6. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: อะไรคือความแตกต่างระหว่างแท็ก `<section>` และ `<article>` ในมาตรฐาน HTML5?
**แนวทางคำตอบ**:
- `<article>` มีความเป็นเอกเทศและสมบูรณ์ในตัวเอง (Self-contained) สามารถหยิบยกเนื้อหานี้ไปเผยแพร่ที่อื่นหรือนำเข้า RSS feed ได้โดยยังคงเข้าใจเนื้อหาได้ครบถ้วน เช่น โพสต์บทความ, ความคิดเห็นของผู้ใช้, การ์ดสินค้า
- `<section>` เป็นเพียงการแบ่งหมวดหมู่ย่อยของเนื้อหาที่มีธีมเรื่องเดียวกัน และตามมาตรฐาน W3C แท็ก `<section>` ควรมีหัวข้อ Heading (`<h2>`-`<h6>`) อยู่ภายในเพื่ออธิบายว่ากลุ่มเนื้อหานี้คือเรื่องอะไร

### Q2: แท็ก `<main>` มีข้อจำกัดในการใช้งานตามข้อกำหนด HTML5 อย่างไรบ้าง?
**แนวทางคำตอบ**:
1. เอกสาร HTML ต้องมีแท็ก `<main>` ที่มองเห็นได้เพียง **1 ตัวเท่านั้นต่อหนึ่งหน้าเว็บ** (ห้ามมี `<main>` ซ้ำซ้อน)
2. แท็ก `<main>` ห้ามเป็นลูกหลาน (Descendant) ของแท็ก `<header>`, `<nav>`, `<aside>`, หรือ `<footer>` โดยเด็ดขาด
3. เนื้อหาภายใน `<main>` ต้องเป็นเนื้อหาหลักที่เป็นเอกลักษณ์เฉพาะของหน้านั้นๆ ไม่ควรนำเนื้อหาที่ซ้ำซ้อนในทุกหน้า (เช่น ลิงก์นำทาง, โลโก้, ข้อมูลลิขสิทธิ์) เข้ามาใส่ใน `<main>`
