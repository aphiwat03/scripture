## 1. แนวคิด (Concept)

การนำเสนอข้อมูลที่มีความสัมพันธ์กันสามารถแบ่งออกได้เป็น 2 มิติหลัก:
- **Lists**: การนำเสนอข้อมูลแบบ 1 มิติ (รายการตามลำดับหรือไม่มีลำดับ)
  - `<ul>` (Unordered List): รายการที่ไม่เน้นลำดับ (เช่น จุดเด่นสินค้า, รายชื่อเมนู)
  - `<ol>` (Ordered List): รายการที่มีลำดับขั้นตอนชัดเจน (เช่น ขั้นตอนการชำระเงิน, วิธีทำอาหาร)
  - `<dl>`, `<dt>`, `<dd>` (Description List): รายการคู่คำศัพท์และคำอธิบาย (Key-Value Pairs เช่น ข้อมูลจำเพาะของฮาร์ดแวร์)
- **Tables (`<table>`)**: การนำเสนอข้อมูลแบบ 2 มิติ (แถวและคอลัมน์) ที่ต้องการความสัมพันธ์ของข้อมูลแบบตาราง เช่น รายการธุรกรรมทางการเงิน, สรุปยอดขาย, หรือตารางเปรียบเทียบแพ็กเกจ

---

## 2. หลักการเบื้องหลัง (Under the Hood)

1. **Accessibility Tree ใน Lists**: เมื่อ Screen Reader พบแท็ก `<ul>` หรือ `<ol>` มันจะประกาศว่า *"List, 4 items"* ช่วยให้ผู้ใช้ทราบว่ามีรายการทั้งหมดกี่ข้อ และกำลังอ่านอยู่ที่ข้อใด การเอาแท็กอื่น (เช่น `<div>`) ไปวางเป็นลูกตรงๆ ของ `<ul>` จะทำให้ Screen Reader อ่านจำนวนข้อผิดพลาด
2. **Accessible Table Navigation**: การใส่ `<th>` พร้อมแอตทริบิวต์ `scope="col"` (หัวตารางแนวตั้ง) หรือ `scope="row"` (หัวตารางแนวนอน) ทำให้เมื่อผู้ใช้เลื่อนดูข้อมูลในแต่ละช่อง (Cell) โปรแกรมอ่านหน้าจอจะขานชื่อหัวคอลัมน์กำกับด้วยเสมอ

## 3. ตัวอย่างโค้ด (HTML5)

### ตัวอย่างที่ 1: ตารางสรุปรายการคำสั่งซื้อ (Order Summary Table)

```html filename="order-table.html"
<table class="order-table">
  <caption>สรุปรายการคำสั่งซื้อรหัส #ORD-2026-889</caption>
  
  <thead>
    <tr>
      <!-- scope="col" กำหนดให้ช่องนี้เป็นหัวแถวของคอลัมน์ด้านล่างทั้งหมด -->
      <th scope="col">รหัสสินค้า</th>
      <th scope="col">ชื่อสินค้า</th>
      <th scope="col">จำนวน</th>
      <th scope="col">ราคาต่อหน่วย</th>
      <th scope="col">รวม (บาท)</th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <th scope="row">SKU-001</th>
      <td>คีย์บอร์ดกลไกไร้สาย</td>
      <td>1</td>
      <td>฿3,500</td>
      <td>฿3,500</td>
    </tr>
    <tr>
      <th scope="row">SKU-002</th>
      <td>แผ่นรองเมาส์หนังแท้</td>
      <td>2</td>
      <td>฿450</td>
      <td>฿900</td>
    </tr>
  </tbody>

  <tfoot>
    <tr>
      <!-- colspan="4" รวม 4 คอลัมน์เข้าด้วยกัน -->
      <th scope="row" colspan="4">ยอดรวมสุทธิ (รวมภาษีมูลค่าเพิ่ม 7%)</th>
      <td><strong>฿4,400</strong></td>
    </tr>
  </tfoot>
</table>
```

### ตัวอย่างที่ 2: การใช้ Description List (`<dl>`) สำหรับสเปกสินค้า

```html filename="product-specs.html"
<section class="specs">
  <h3>ข้อมูลจำเพาะทางเทคนิค (Technical Specifications)</h3>
  
  <dl class="specs-list">
    <dt>ชิปประมวลผล</dt>
    <dd>Apple M4 Pro (14-Core CPU)</dd>

    <dt>หน่วยความจำ (RAM)</dt>
    <dd>48GB Unified Memory</dd>

    <dt>การเชื่อมต่อไร้สาย</dt>
    <dd>Wi-Fi 7 (802.11be)</dd>
    <dd>Bluetooth 5.4</dd>
  </dl>
</section>
```

## 4. โค้ดที่มักเขียนผิด vs โค้ดที่ถูกต้อง

### ❌ โค้ดที่ผิด: ใช้ `<table>` ในการจัด Layout หน้าเว็บ

```html
<!-- ผิด: Anti-pattern ในยุค 90s ใช้ตารางแบ่งคอลัมน์หน้าเว็บ -->
<table width="100%">
  <tr>
    <td width="20%">เมนูด้านข้าง</td>
    <td width="80%">เนื้อหาหลักของเว็บไซต์</td>
  </tr>
</table>
```
*ผลกระทบ*: ทำลายระบบ Responsive Design บนหน้าจอมือถือ และทำให้ Screen Reader พยายามอ่านหน้าเว็บเป็นข้อมูลตาราง ซึ่งสร้างความสับสนอย่างรุนแรง

### ✅ โค้ดที่ถูกต้อง: ใช้ CSS Grid / Flexbox จัด Layout และใช้แท็ก Semantic

```html
<!-- ถูกต้อง: ใช้ Semantic Tags ร่วมกับ CSS Layout -->
<div class="layout-container" style="display: grid; grid-template-columns: 240px 1fr;">
  <aside>เมนูด้านข้าง</aside>
  <main>เนื้อหาหลักของเว็บไซต์</main>
</div>
```

## 5. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้ Tables
- ข้อมูลที่มีลักษณะเป็น **Tabular Data อย่างแท้จริง** ที่มีหัวข้อคอลัมน์และแถวชัดเจน (เช่น งบการเงิน, ตารางเรียน, สถิติการขาย)

### ไม่ควรใช้ Tables
- **ห้ามใช้จัด Layout ของหน้าเว็บเด็ดขาด**: ให้ใช้ CSS Flexbox หรือ CSS Grid แทน
- หากเป็นเพียงรายการข้อมูลข้อความบรรทัดเดียว ให้ใช้ `<ul>` หรือ `<ol>`

## 6. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: ทำไมในปัจจุบันจึงมีข้อห้ามอย่างเด็ดขาดว่า "ห้ามใช้ `<table>` ในการจัด Layout หน้าเว็บ"?
**แนวทางคำตอบ**: มี 3 สาเหตุหลัก:
1. **Accessibility**: ตารางจะส่งสัญญาณไปยัง Accessibility API ว่าเนื้อหานี้เป็นชุดข้อมูลที่มีความสัมพันธ์เชิงตัวเลข ทำให้ Screen Reader นำทางแบบตาราง (Matrix) แทนที่จะอ่านเป็นเนื้อหาเอกสารปกติ
2. **Responsive Design**: ตารางจัดการขนาดยากมากบนหน้าจอมือถือ ไม่รองรับการตัดบรรทัดหรือสลับเลย์เอาต์ที่ยืดหยุ่นเหมือน Flexbox หรือ Grid
3. **Performance & Rendering**: เบราว์เซอร์ต้องรอคำนวณขนาดของ Cell ทั้งหมดในตารางให้เสร็จก่อน จึงจะสามารถเรนเดอร์โครงสร้างได้ ทำให้เกิดปัญหาบล็อกการแสดงผล (Reflow Overhead)

### Q2: แอตทริบิวต์ `scope` ในแท็ก `<th>` มีประโยชน์อย่างไร?
**แนวทางคำตอบ**: แอตทริบิวต์ `scope` (ค่าที่เป็นไปได้คือ `col`, `row`, `colgroup`, `rowgroup`) ช่วยระบุความสัมพันธ์ทางโครงสร้างอย่างชัดเจนว่า เซลล์หัวตารางนี้กำลังควบคุมเซลล์ข้อมูลในทิศทางใด ช่วยให้โปรแกรม Screen Reader สามารถอ่านค่าหัวข้อที่สอดคล้องกับช่องข้อมูลนั้นได้อย่างถูกต้องเสมอเมื่อผู้ใช้เลื่อนลูกศรสำรวจตาราง
