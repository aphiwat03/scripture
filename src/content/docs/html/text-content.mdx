## 1. แนวคิด (Concept)

การจัดรูปแบบข้อความใน HTML ไม่ใช่เพียงการทำให้ตัวหนังสือ "ดูหนา" หรือ "ดูเอียง" แต่คือการให้ **"น้ำหนักและความหมายเชิงความสำคัญ (Semantic Weight)"** แก่เนื้อหา

- **Headings (`<h1>` - `<h6>`)**: เปรียบเหมือน **"สารบัญและหัวข้อย่อยของหนังสือ"** ที่บอกโครงสร้างลำดับความสำคัญของเอกสาร
- **Paragraph (`<p>`)**: ข้อความบรรยายหนึ่งย่อหน้าที่มีใจความสมบูรณ์
- **`<strong>` vs `<b>`**:
  - `<strong>`: หมายถึงข้อความที่มีความสำคัญยิ่งยวดหรือเร่งด่วน (Screen Reader จะเน้นเสียงดังขึ้น)
  - `<b>`: ตัวหนาเพื่อดึงดูดสายตาเฉยๆ โดยไม่มีนัยยะความสำคัญเพิ่มขึ้น
- **`<em>` vs `<i>`**:
  - `<em>`: Stress Emphasis (เน้นย้ำน้ำเสียงในการพูด)
  - `<i>`: Idiomatic Text เช่น คำศัพท์ภาษาต่างประเทศ, ศัพท์เทคนิค, ชื่อเรือ, หรือความคิดในใจ
- **`<hr>`**: ตัวคั่นการเปลี่ยนเนื้อหาใจความ (Thematic Break)
- **`<br>`**: การตัดขึ้นบรรทัดใหม่เฉพาะกรณีที่จำเป็นจริง (เช่น ที่อยู่, กลอน)

## 2. หลักการเบื้องหลัง (Under the Hood)

1. **Accessibility Tree & Screen Reader Navigation**: ผู้พิการทางสายตามักไม่ได้ฟังเว็บไซต์ตั้งแต่บรรทัดแรกจนบรรทัดสุดท้าย แต่จะใช้ปุ่มลัด (เช่น กดแป้น `H` ใน NVDA/JAWS) เพื่อกระโดดข้ามตามแท็ก Heading หากลำดับของ Heading ข้ามขั้น (เช่น จาก `<h1>` ข้ามไป `<h4>`) ผู้ใช้จะเข้าใจผิดว่าเนื้อหาส่วนก่อนหน้านั้นหายไป
2. **SEO Semantic Parsing**: Search Engine Bots (Googlebot) ให้น้ำหนักของคีย์เวิร์ดใน `<h1>` สูงที่สุดในฐานะหัวข้อหลักของหน้านั้น และใช้ลำดับ Heading ในการสร้าง Rich Snippets บนผลการค้นหา

## 3. ตัวอย่างโค้ด (HTML5)

### ตัวอย่างที่ 1: โครงสร้างบทความบล็อกเชิงเทคนิค (Technical Blog Post)

```html filename="blog-article.html"
<article class="post">
  <!-- <h1> มีได้เพียง 1 อันต่อหน้า สำหรับเป็นหัวข้อหลัก -->
  <h1>คู่มือเริ่มต้นเรียนรู้ Next.js 16 และ React 19</h1>

  <p class="post-meta">
    เผยแพร่เมื่อ: <time datetime="2026-10-17">17 ตุลาคม 2026</time> โดย <strong>ทีมงานวิศวกรรม</strong>
  </p>

  <!-- <h2> หัวข้อย่อยระดับแรก -->
  <h2>1. ข้อแตกต่างของ Server Components</h2>
  <p>
    React Server Components ช่วยลดขนาด JavaScript Bundle ฝั่ง Client 
    ได้อย่างมหาศาล <em>โดยประมวลผลล่วงหน้าบนเซิร์ฟเวอร์</em>
  </p>

  <!-- <h3> หัวข้อย่อยภายใต้ <h2> -->
  <h3>ประสิทธิภาพในการประมวลผล (Performance Benchmark)</h3>
  <p>
    จากการทดสอบพบว่าสามารถเพิ่มคะแนน <i>First Contentful Paint (FCP)</i> ได้มากกว่า <strong>40%</strong>
  </p>

  <!-- <hr> คั่นเมื่อเปลี่ยนผ่านช่วงบทความ -->
  <hr>

  <h2>2. การเตรียมความพร้อมก่อนอัปเกรด</h2>
  <p>
    ตรวจสอบเวอร์ชันของ Node.js ให้เป็นเวอร์ชัน <strong>20.x ขึ้นไป</strong> เสมอ
  </p>
</article>
```

### ตัวอย่างที่ 2: การใช้ `<br>` อย่างถูกต้องในที่อยู่จัดส่งสินค้า

```html filename="shipping-address.html"
<section class="shipping-info">
  <h2>ที่อยู่สำหรับออกใบกำกับภาษี</h2>
  <!-- ใช้ <address> ร่วมกับ <br> ในกรณีที่เป็นที่อยู่จริงตามมาตรฐาน HTML5 -->
  <address>
    บริษัท สคริปเจอร์ เทคโนโลยี จำกัด<br>
    อาคาร ดิจิทัล ทาวเวอร์ ชั้น 18 ห้อง 1804<br>
    ถนนสุขุมวิท แขวงคลองเตย เขตคลองเตย<br>
    กรุงเทพมหานคร 10110
  </address>
</section>
```

## 4. โค้ดที่มักเขียนผิด vs โค้ดที่ถูกต้อง

### ❌ โค้ดที่ผิด: ข้ามระดับ Heading และใช้ `<br>` หลายอันแทน CSS Margin

```html
<!-- ผิด: มี <h1> ซ้ำซ้อน และข้ามจาก <h1> ไป <h4> เพียงเพราะต้องการตัวอักษรขนาดเล็กลง -->
<h1>ร้านค้าออนไลน์</h1>
<h1>สินค้าขายดีประจำสัปดาห์</h1>
<h4>หูฟังบลูทูธ</h4>

<!-- ผิด: ใช้ <br> รัวๆ เพื่อดันระยะห่างด้านล่าง -->
<p>ขอบคุณสำหรับการสั่งซื้อ</p>
<br><br><br>
<button>กลับสู่หน้าหลัก</button>
```

### ✅ โค้ดที่ถูกต้อง: เรียงลำดับ Heading สม่ำเสมอ และเว้นระยะห่างด้วย CSS

```html
<!-- ถูกต้อง: <h1> 1 ตัว และย่อยลงมาเป็น <h2> ตามลำดับตรรกะ -->
<header>
  <h1>ร้านค้าออนไลน์</h1>
</header>

<main>
  <section>
    <h2>สินค้าขายดีประจำสัปดาห์</h2>
    <h3>หูฟังบลูทูธไร้สาย</h3>
  </section>

  <!-- ถูกต้อง: เว้นระยะห่างด้วย Class Margin ใน CSS -->
  <div class="checkout-complete" style="margin-bottom: 2rem;">
    <p>ขอบคุณสำหรับการสั่งซื้อ</p>
  </div>
  <button type="button">กลับสู่หน้าหลัก</button>
</main>
```

## 5. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรทำ
- ใช้ `<h1>` เพียงแท็กเดียวต่อหน้าเว็บสำหรับหัวข้อสำคัญที่สุด
- เรียงลำดับ Heading ตามลำดับความสำคัญของโครงสร้างเนื้อหาเสมอ (`h1` → `h2` → `h3`)
- ปรับขนาดตัวอักษรด้วย CSS (`font-size`) ห้ามเลือกแท็ก Heading เพียงเพราะต้องการตัวหนังสือเล็กหรือใหญ่

### ไม่ควรทำ
- **ห้ามใช้ `<br><br><br>` เพื่อเว้นระยะบรรทัด**: ควรใช้ CSS `margin` หรือ `gap` ใน Flexbox/Grid
- **ห้ามใช้ `<b>` หรือ `<i>` เพื่อแต่งสไตล์ความสวยงาม**: ให้ใช้ CSS `font-weight` หรือ `font-style` แทน

## 6. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: ความแตกต่างระหว่างแท็ก `<strong>` กับ `<b>` และแท็ก `<em>` กับ `<i>` คืออะไร?
**แนวทางคำตอบ**:
- `<strong>` มีความหมายทาง Semantic ว่าข้อความนี้สำคัญยิ่งยวดหรือเร่งด่วน โดยโปรแกรม Screen Reader จะเน้นเสียงดังขึ้น ในขณะที่ `<b>` เป็นเพียงการทำให้ข้อความตัวหนาเพื่อดึงดูดสายตาทางกายภาพโดยไม่มีนัยยะความสำคัญ
- `<em>` หมายถึงการเน้นย้ำน้ำเสียง (Emphasis) มีผลต่อความหมายและเสียงพูดของประโยค ส่วน `<i>` เป็น Idiomatic Text ใช้กับคำที่ต้องการแยกออกจากข้อความปกติ เช่น ศัพท์ภาษาต่างประเทศ, ศัพท์เทคนิค, หรือชื่อหนังสือ

### Q2: ทำไมการเรียงลำดับ Heading (h1-h6) โดยไม่ข้ามขั้นจึงมีความสำคัญอย่างยิ่งต่อ Accessibility (a11y)?
**แนวทางคำตอบ**: ผู้พิการทางสายตาที่ใช้ Screen Reader จะอาศัยปุ่มลัดเพื่อสำรวจสารบัญของหน้าเว็บผ่าน Heading การที่ลำดับ Heading มีความต่อเนื่องเป็นลำดับขั้น (Tree Hierarchy) เช่น จาก `h1` ลงมา `h2` และ `h3` ช่วยให้ผู้ใช้เข้าใจความสัมพันธ์ของเนื้อหาหลักและเนื้อหาย่อยได้อย่างถูกต้อง การข้ามขั้นอย่าง `h1` ไป `h4` จะทำให้ผู้ใช้สับสนและคิดว่ามีเนื้อหาส่วนใดตกหล่นไป
