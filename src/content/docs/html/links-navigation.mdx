## 1. แนวคิด (Concept)

Hyperlink (`<a>` ย่อมาจาก Anchor) คือหัวใจหลักที่ทำให้ **World Wide Web** เชื่อมโยงเข้าหากันเป็นใยแมงมุม มันช่วยให้ผู้ใช้สามารถเดินทางข้ามระหว่างหน้าเอกสาร เว็บไซต์ภายนอก หรือกระโดดไปยังจุดต่างๆ ภายในหน้าเดียวกันได้

ประเภทของ `href`:
- **Absolute URL**: ระบุที่อยู่เต็มรูปแบบ เช่น `https://google.com` (ใช้เชื่อมต่อไปยังโดเมนอื่น)
- **Relative URL**: ระบุตำแหน่งสัมพันธ์กับหน้าปัจจุบัน เช่น `/about` หรือ `../products`
- **Anchor Link**: กระโดดไปยังตำแหน่ง ID ในหน้าเดียวกัน เช่น `#pricing`
- **Protocol Links**: สั่งการแอประบบ เช่น `mailto:support@company.com` หรือ `tel:+6621234567`

## 2. หลักการเบื้องหลัง (Under the Hood)

### ภัยคุกคาม Reverse Tabnabbing และ `target="_blank"`
เมื่อเปิดลิงก์ไปยังเว็บไซต์ภายนอกด้วย `target="_blank"` หน้าต่างแท็บใหม่ที่เปิดขึ้นมาจะสามารถเข้าถึง Object `window.opener` ของแท็บเดิมได้ ทำให้เว็บปลายทางที่อันตรายสามารถสั่ง:
```javascript
// เว็บไซต์อันตรายสั่งเปลี่ยนหน้าเว็บเดิมของผู้ใช้เป็นหน้า Phishing หลอกเอา Password
window.opener.location = "https://evil-phishing-login.com";
```
การใส่ `rel="noopener noreferrer"` จึงเป็นหัวใจสำคัญ:
- **`noopener`**: ป้องกันไม่ให้แท็บใหม่เข้าถึง `window.opener`
- **`noreferrer`**: ป้องกันไม่ให้เบราว์เซอร์ส่ง HTTP Referer Header ออกไป (ปกป้องข้อมูลส่วนตัวของ URL ต้นทาง)

*(หมายเหตุ: เบราว์เซอร์สมัยใหม่ส่วนใหญ่ตั้งค่าเริ่มต้นให้ `target="_blank"` มีพฤติกรรม `noopener` อัตโนมัติแล้ว แต่ยังถือเป็น Best Practice สากลที่ต้องระบุไว้อย่างชัดเจนเสมอ)*

## 3. ตัวอย่างโค้ด (HTML5)

### ตัวอย่างที่ 1: เมนูนำทาง (Navigation Bar) และ Footer Links

```html filename="navbar.html"
<nav aria-label="เมนูหลักของเว็บไซต์">
  <ul>
    <!-- Relative Link: ภายในเว็บเดียวกัน -->
    <li><a href="/">หน้าแรก</a></li>
    <li><a href="/products">สินค้าทั้งหมด</a></li>

    <!-- Anchor Link: เลื่อนไปยัง Section ราคาในหน้าเดียวกัน -->
    <li><a href="#pricing-section">ตารางราคา</a></li>

    <!-- Protocol Link: เปิดแอปโทรศัพท์บนมือถือ -->
    <li><a href="tel:021234567">ติดต่อด่วน: 02-123-4567</a></li>
  </ul>
</nav>
```

### ตัวอย่างที่ 2: ลิงก์ออกไปภายนอกที่ปลอดภัย พร้อม Accessible Name

```html filename="external-links.html"
<section class="partner-section">
  <h2>พาร์ทเนอร์และช่องทางโซเชียลมีเดีย</h2>
  
  <!-- ลิงก์ภายนอกที่ปลอดภัย 100% -->
  <p>
    ติดตามข่าวสารอัปเดตระบบได้ที่ 
    <a 
      href="https://github.com/example/scripture" 
      target="_blank" 
      rel="noopener noreferrer"
      aria-label="GitHub ของโปรเจกต์ Scripture (เปิดในแท็บใหม่)"
    >
      GitHub ทางการ
      <!-- SVG ไอคอนบอกว่าเปิดแท็บใหม่ -->
      <span aria-hidden="true">↗</span>
    </a>
  </p>
</section>
```

## 4. โค้ดที่มักเขียนผิด vs โค้ดที่ถูกต้อง

### ❌ โค้ดที่ผิด: ใช้ `<a>` ทำหน้าที่เป็นปุ่มกด JavaScript

```html
<!-- ผิด: ใช้ <a> แต่ไม่มี URL ปลายทางจริง เป็น Anti-pattern ร้ายแรง -->
<a href="#" onclick="openModal()">เปิดหน้าต่างยืนยัน</a>
<a href="javascript:void(0)" onclick="deleteItem()">ลบรายการ</a>
```
*ผลกระทบ*: กดแป้น Tab หรือ Enter จากคีย์บอร์ดแล้วไม่เป็นไปตามธรรมชาติ และผู้พิการที่ใช้ Screen Reader จะได้ยินว่านี่คือลิงก์ แต่กดแล้วไม่เกิดการเปลี่ยนหน้า

### ✅ โค้ดที่ถูกต้อง: แยกหน้าที่ ลิงก์สำหรับเดินทาง ปุ่มสำหรับการกระทำ

```html
<!-- ถูกต้อง: ถ้าเป็นการกระทำภายในหน้า (เปิด Modal, ลบข้อมูล) ให้ใช้ <button> เสมอ -->
<button type="button" onclick="openModal()">เปิดหน้าต่างยืนยัน</button>
<button type="button" class="btn-danger" onclick="deleteItem()">ลบรายการ</button>
```

## 5. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้แท็ก `<a>`
- เมื่อต้องการให้เบราว์เซอร์ **เปลี่ยน URL หรือเปลี่ยนหน้าจอ**
- เมื่อต้องการให้ผู้ใช้สามารถคลิกขวาแล้วเลือก "Open link in new tab" หรือ Bookmark หน้านั้นได้
- เมื่อต้องการดาวน์โหลดไฟล์ (ร่วมกับแอตทริบิวต์ `download`)

### ไม่ควรใช้แท็ก `<a>`
- ห้ามใช้ `<a>` เป็นปุ่มกดสำหรับ Trigger การกระทำเช่น ส่งฟอร์ม, เปิด/ปิด Dropdown, เล่นเพลง, หรือลบข้อมูล ให้ใช้ `<button type="button">` เสมอ

## 6. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: ทำไมการใช้ `target="_blank"` จึงต้องใส่ `rel="noopener noreferrer"` เสมอ?
**แนวทางคำตอบ**: เพื่อป้องกันช่องโหว่ด้านความปลอดภัยที่เรียกว่า **Reverse Tabnabbing** เนื่องจากหน้าต่างใหม่ที่เปิดขึ้นผ่าน `target="_blank"` จะมีสิทธิ์เข้าถึง `window.opener` ของหน้าต่างเดิม ซึ่งเปิดช่องให้ผู้ไม่หวังดีแอบสั่งเปลี่ยนเส้นทางของหน้าต่างเดิมไปยังเว็บไซต์หลอกลวง (Phishing Site) ได้ การใส่ `noopener` จะตัดการเชื่อมต่อ `window.opener` ให้เป็น null ส่วน `noreferrer` จะไม่ส่ง Referer Header ปลายทางเพื่อความเป็นส่วนตัว

### Q2: ในการทำ Web Accessibility (a11y) ทำไมจึงไม่ควรเขียนข้อความลิงก์ว่า "คลิกที่นี่ (Click here)"?
**แนวทางคำตอบ**: เพราะผู้ใช้ Screen Reader มักจะเปิดดูรายชื่อลิงก์ทั้งหมดในหน้า (Links List) เพื่อเลือกหน้าที่ต้องการไปอย่างรวดเร็ว หากลิงก์มีข้อความแค่ว่า "คลิกที่นี่" หรือ "อ่านเพิ่มเติม" ผู้ใช้จะไม่รู้เลยว่าลิงก์นั้นจะพาไปที่ไหน ลิงก์ที่ดีควรมีความหมายในตัวเอง (Descriptive Link Text) เช่น *"อ่านคู่มือการติดตั้ง Next.js 16"* หรือหากจำเป็นต้องใช้ข้อความสั้น ให้เสริมคำอธิบายผ่าน `aria-label`
