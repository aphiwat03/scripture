## 1. แนวคิด (Concept)

เมื่อเกิดปัญหา "สไตล์ไม่ติด", "ขอบเกินล้นจอ", หรือ "สีไม่เปลี่ยนตามที่เขียน" ทักษะสำคัญที่สุดของ Fullstack Developer คือ **"การสืบสวนด้วยเบราว์เซอร์ DevTools"** แทนที่จะนั่งเดาโค้ดไปเรื่อยๆ

เครื่องมือหลักใน Elements Panel:
- **Inspect Element (Ctrl+Shift+C / Cmd+Opt+C)**: จิ้มดู Element เพื่อดูว่าได้รับคลาสอะไรบ้าง
- **Styles Tab**: ดูว่ามีคำสั่งใดถูกขีดฆ่า (Strikethrough) แปลว่าคำสั่งนั้นแพ้ Specificity หรือถูกเขียนทับ
- **Computed Tab**: แสดงค่าจริงสุดท้าย (Final Rendered Value) ที่เบราว์เซอร์คำนวณและวาดลงบนหน้าจอ
- **Box Model Diagram**: แผนภาพสี่เหลี่ยมสีฟ้า/เขียว/เหลือง/ส้ม ที่บอกตัวเลขชัดเจนของ Content, Padding, Border, Margin
- **Device Mode & Responsive View**: จำลองขนาดหน้าจอมือถือและเครือข่าย

## 2. ขั้นตอนการสืบสวนเมื่อ CSS ไม่ทำงาน (Debugging Workflow)

```
1. จิ้ม Inspect Element
       ↓
2. ดูที่ Styles Tab: มี Property นั้นขึ้นมาไหม?
   ├── ไม่มีเลย -> Selector เขียนผิด หรือ Class ไม่ถูก Compile / ลืม Link ไฟล์
   └── มีแต่โดนขีดฆ่า -> แพ้ Specificity หรือโดนคำสั่งอื่นที่อยู่ล่างกว่าเขียนทับ
       ↓
3. สลับไปที่ Computed Tab: ตรวจสอบค่าจริงสุดท้าย
       ↓
4. ดูที่ Box Model Diagram: กล่องบวมเพราะ Padding หรือติด Margin ล่องหนตัวไหน
```

## 3. เทคนิคเด็ดใน DevTools

### 1. การจำลองสถานะ `:hover` และ `:focus`
ในแท็บ Styles ให้คลิกที่ปุ่ม **`:hov`** คุณจะสามารถติ๊กเลือกสถานะ `:hover`, `:active`, หรือ `:focus-visible` ค้างไว้ได้ เพื่อตรวจสอบสไตล์ของ Dropdown หรือ Tooltip โดยที่เมาส์ไม่ต้องคอยชี้แช่ไว้

### 2. ดู Specificity คะแนนเต็มๆ แค่เอาเมาส์ชี้
ใน Chrome / Edge DevTools รุ่นใหม่ เพียงนำเมาส์ไปชี้เหนือชื่อ Selector (เช่น `.header .btn`) กล่อง Tooltip จะคำนวณคะแนนให้คุณเห็นทันที:
> **Specificity: (0, 2, 0)**

## 4. โค้ดที่มักเข้าใจผิด vs การตรวจสอบผ่าน DevTools

### ❌ ข้อผิดพลาด: พยายามเติม `!important` เพราะคิดว่าโค้ดไม่ติด

```css
/* พฤติกรรมมือใหม่: เติม !important รัวๆ โดยไม่เปิด DevTools เช็ค */
.btn {
  background-color: blue !important;
}
```

### ✅ แนวทางที่ถูกต้อง: เปิด Computed Tab หาตัวการจริง

เมื่อเปิด Computed Tab คุณจะพบคลิกที่ลูกศรเพื่อกระโดดไปยังบรรทัดที่ทำให้สไตล์เดิมถูกทับ ทำให้แก้ปัญหาได้ตรงจุดต้นเหตุโดยไม่ต้องพึ่งพา `!important` เลย

## 5. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: แท็บ "Styles" และแท็บ "Computed" ใน Chrome DevTools มีความแตกต่างกันอย่างไร และควรใช้เมื่อไหร่?
**แนวทางคำตอบ**:
- **Styles Tab**: แสดงรายการ CSS Rules ทั้งหมดที่ตรงกับ Selector ของ Element นั้น รวมถึงกฎที่ถูกขีดฆ่า (Overridden / Strikethrough) และบอกว่าคำสั่งนั้นมาจากไฟล์ใด บรรทัดที่เท่าไหร่ เหมาะสำหรับ **การดูว่ามีสไตล์อะไรมาตีกันและใครแพ้ชนะ**
- **Computed Tab**: แสดงเฉพาะ **ค่าสุดท้ายจริงเพียงค่าเดียว (Final Resolved Value)** ที่เบราว์เซอร์นำไปใช้คำนวณบนหน้าจอ โดยแปลงหน่วยสัมพัทธ์ทั้งหมดเป็นพิกเซล (เช่น แปลง `2rem` เป็น `32px`) เหมาะสำหรับ **การตรวจสอบว่าทำไมค่าจริงไม่ตรงกับที่คิด หรือตรวจสอบว่า Element ได้รับสไตล์ที่สืบทอด (Inherited) มาจากแม่หรือไม่**

### Q2: ใน Box Model Diagram ของ DevTools แต่ละสี (ฟ้า, เขียว, ส้ม, เหลือง) แทนชิ้นส่วนใดของกล่อง?
**แนวทางคำตอบ**:
- **สีฟ้า (Blue)**: Content (พื้นที่เนื้อหาจริงของข้อความหรือรูปภาพ)
- **สีเขียว (Green)**: Padding (ระยะห่างภายในกล่อง)
- **สีเหลือง/น้ำตาล (Yellow/Brown)**: Border (เส้นขอบของกล่อง)
- **สีส้ม (Orange)**: Margin (ระยะห่างภายนอกกล่อง)
