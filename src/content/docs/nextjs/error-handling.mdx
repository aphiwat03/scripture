## 1. คืออะไร / ใช้ทำไม

**Error Handling & Loading UI** คือระบบจัดการหน้าแสดงผลขณะรอข้อมูล (`loading.tsx`) และการดักจับข้อผิดพลาด (`error.tsx`, `not-found.tsx`) โดยอัตโนมัติด้วย React Suspense และ Error Boundary ระดับ Route

ช่วยป้องกันไม่ให้หน้าเว็บล่มทั้งระบบเมื่อเกิดข้อผิดพลาดเฉพาะจุด (Graceful Degradation) และสร้างความรู้สึกตอบสนองที่รวดเร็วให้แก่ผู้ใช้งาน

## 2. ตัวอย่างโค้ด (TypeScript)

### การสร้าง Loading Skeleton

```tsx filename="src/app/dashboard/loading.tsx"
// Next.js จะนำไปหุ้ม page.tsx ด้วย <Suspense> ให้อัตโนมัติ
export default function DashboardLoading() {
  return (
    <div className="animate-pulse space-y-4 max-w-xl mx-auto py-8">
      <div className="h-8 bg-hairline/60 rounded-xl w-1/3" />
      <div className="h-48 bg-hairline/60 rounded-2xl" />
      <div className="h-32 bg-hairline/60 rounded-2xl" />
    </div>
  );
}
```

### การดักจับ Error ด้วย Error Boundary

```tsx filename="src/app/dashboard/error.tsx"
'use client'; // Error Component ต้องเป็น Client Component เสมอ

export default function DashboardError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return (
    <div className="p-8 text-center border border-red-500/20 rounded-2xl bg-red-500/[0.04] max-w-md mx-auto my-8">
      <h2 className="text-xl font-bold text-red-500">เกิดข้อผิดพลาดในการโหลดข้อมูล</h2>
      <p className="text-sm text-muted mt-2">{error.message}</p>
      <button
        type="button"
        onClick={() => reset()}
        className="mt-4 px-4 py-2 bg-red-600 text-white rounded-xl text-xs font-semibold hover:bg-red-700 transition"
      >
        ลองใหม่อีกครั้ง
      </button>
    </div>
  );
}
```

## 3. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

- **`loading.tsx`**: วางไว้ในโฟลเดอร์ Route เพื่อแสดง Skeleton ทันทีที่ผู้ใช้คลิกเปลี่ยนหน้า โดยไม่ต้องเขียน state `isLoading` เองในคอมโพเนนต์
- **`error.tsx`**: ใช้ดักจับข้อผิดพลาดเฉพาะส่วนของหน้านั้น ช่วยให้ส่วนอื่นๆ ของเว็บ (เช่น Navbar/Sidebar) ยังใช้งานได้ตามปกติ
- **`not-found.tsx`**: ใช้ร่วมกับฟังก์ชัน `notFound()` จาก `next/navigation` เมื่อไม่พบข้อมูลในฐานข้อมูล

## 4. ข้อควรระวัง

<Callout type="warning" title="error.tsx ต้องเป็น Client Component เสมอ">
ไฟล์ `error.tsx` ต้องระบุ `'use client'` บรรทัดแรกสุดเสมอ เพราะ Error Boundary ใน React สามารถทำงานได้เฉพาะบนฝั่ง Client เท่านั้น
</Callout>

<Callout type="tip" title="การใช้ global-error.tsx">
`error.tsx` ภายในโฟลเดอร์ `app/` จะไม่สามารถดักจับ Error ที่เกิดขึ้นใน Root `layout.tsx` ได้ หากต้องการดักจับ Error ของ Root Layout ให้สร้างไฟล์ `app/global-error.tsx`
</Callout>
