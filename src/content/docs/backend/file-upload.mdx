# File Upload

ในระบบอีคอมเมิร์ซระดับ Production อย่าง **Smart Butcher Marketplace** การจัดการไฟล์อัปโหลด (File Upload) เป็นองค์ประกอบสำคัญที่ต้องรองรับทั้งไฟล์สาธารณะ เช่น รูปภาพสินค้าเนื้อวากิว (`Product.imageUrl`) และไฟล์ที่มีความลับทางธุรกิจสูง เช่น สลิปโอนเงินของลูกค้า (`Payment.slipImageUrl`) การออกแบบระบบอัปโหลดไฟล์ที่ดีใน NestJS 11 จึงต้องคำนึงถึงความเสถียรของหน่วยความจำ ความปลอดภัยในการตรวจสอบไฟล์จริงระดับไบต์ (Magic Number) การแยกพื้นที่จัดเก็บบน Cloud Object Storage (Supabase Storage) และการจัดการไฟล์ขยะ (Orphaned Files) อย่างรัดกุม

| หัวข้อในหน้านี้ | รายละเอียดหลัก |
| :--- | :--- |
| [1. สถาปัตยกรรม End-to-End File Upload Flow ด้วย Multer ใน NestJS 11](/docs/backend/file-upload/multer-pipeline) | การทำงานของ `multipart/form-data`, `FileInterceptor` และการใช้ `memoryStorage` |
| [2. การตรวจสอบความถูกต้องของไฟล์ด้วย ParseFilePipe และ Magic Number](/docs/backend/file-upload/magic-number) | การจำกัดขนาดไฟล์และการตรวจจับ File Signature ระดับไบต์เพื่อป้องกันการปลอมนามสกุลไฟล์ |
| [3. การอัปโหลดไฟล์ขึ้น Supabase Storage และการตั้งชื่อไฟล์ไม่ให้ซ้ำ](/docs/backend/file-upload/supabase-storage) | การสร้าง `StorageService` ด้วย `@supabase/supabase-js` และการตั้งชื่อไฟล์ด้วย `crypto.randomUUID()` |
| [4. Public vs Private Buckets, Signed URLs และการจัดการสลิปโอนเงินอย่างปลอดภัย](/docs/backend/file-upload/signed-urls) | การแยกระดับสิทธิ์ Bucket และการสร้าง Temporary Signed URL สำหรับตรวจสอบสลิปโอนเงิน |
| [5. การซิงค์และลบไฟล์ขยะ (Orphaned Files Cleanup) เมื่อลบข้อมูลในฐานข้อมูล](/docs/backend/file-upload/orphan-cleanup) | กลยุทธ์การลบไฟล์เก่าเมื่อเปลี่ยนรูปสินค้าหรือเมื่อเกิด Rollback ในฐานข้อมูล |
| [ข้อผิดพลาดที่พบบ่อย (Anti-patterns)](/docs/backend/file-upload/pitfalls) | ข้อควรระวังในการจัดการไฟล์บน Containerized Backend |
| [Checklist สรุป](/docs/backend/file-upload/pitfalls) | รายการตรวจสอบความพร้อมก่อนขึ้นระบบจริง |
| [ลำดับการเรียนที่แนะนำ และ ดูเพิ่มเติมที่](/docs/backend/file-upload/pitfalls) | เส้นทางการศึกษาต่อยอดในส่วน Backend และ Database |
