# Docker

ในการพัฒนาระบบ **Smart Butcher Marketplace** ปัญหาคลาสสิกที่ทีมพัฒนาพบบ่อยคือ *"รันบนเครื่องตัวเองผ่าน แต่พอขึ้นเซิร์ฟเวอร์จริงกลับพัง"* (Works on my machine) เนื่องจากความแตกต่างของเวอร์ชัน Node.js, ไลบรารีระดับ OS สำหรับ Prisma Client หรือการตั้งค่า PostgreSQL 16 การนำ **Docker Engine** และ **Docker Compose v2** มาใช้ช่วยมาตรฐานสภาพแวดล้อมตั้งแต่เครื่องนักพัฒนา (Local Development), ระบบ CI/CD ไปจนถึง Production Server ให้เหมือนกันทุกประการ พร้อมทั้งจำกัดทรัพยากรและยกระดับความปลอดภัยของระบบ

| หัวข้อในหน้านี้ | รายละเอียดหลัก |
| :--- | :--- |
| [1. แนวคิดหลักของ Docker (Image, Container, Volume, Network)](/docs/backend/docker/docker-concepts) | สถาปัตยกรรม Containerization, UnionFS Layers และความแตกต่างจาก Virtual Machine |
| [2. การเขียน Multi-stage Dockerfile สำหรับ NestJS 11 ระดับ Production](/docs/backend/docker/multi-stage-build) | การลดขนาด Image, การสร้าง Prisma Client, การรันด้วย Non-root User และ `.dockerignore` |
| [3. การประกอบระบบด้วย Docker Compose (NestJS + PostgreSQL 16)](/docs/backend/docker/docker-compose) | การผสานระบบ Backend API และฐานข้อมูลให้ทำงานร่วมกันด้วยไฟล์ `compose.yaml` |
| [4. การจัดการ Persistent Volumes, Environment Variables, Secrets และ Healthcheck](/docs/backend/docker/volumes-health) | การรักษาข้อมูลสต็อกเนื้อและคำสั่งซื้อไม่ให้สูญหาย และการควบคุมลำดับการบูตด้วย `healthcheck` |
| [5. การเชื่อมต่อเครือข่ายระหว่าง Container และคำสั่ง CLI สำหรับ Debug](/docs/backend/docker/network-debug) | ระบบ Internal DNS ของ Docker Network และชุดคำสั่งตรวจสอบระบบเมื่อเกิดปัญหา |
| [ข้อผิดพลาดที่พบบ่อย (Anti-patterns)](/docs/backend/docker/pitfalls) | ข้อควรระวังในการเขียน Dockerfile และ Compose สำหรับ Node.js / NestJS |
| [Checklist สรุป](/docs/backend/docker/pitfalls) | รายการตรวจสอบความพร้อมของระบบ Container ก่อนขึ้น Production |
