## 1. แนวคิด (Concept)

สองเสาหลักที่ชี้ชะตาความสำเร็จของเว็บแอปพลิเคชันระดับโลกคือ **Accessibility (การเข้าถึงได้อย่างเท่าเทียมตามเกณฑ์ WCAG 2.1)** และ **Performance (ประสิทธิภาพและความเร็วของ Bundle Size)**

shadcn/ui สร้างขึ้นเพื่อพิชิตทั้งสองเป้าหมายนี้โดยไม่มีการประนีประนอม:
1. **Accessibility มอบโดย Radix UI**: ผ่านเกณฑ์ WAI-ARIA Authoring Practices สมบูรณ์แบบ รองรับผู้ใช้งานทุกกลุ่ม รวมถึงผู้พิการทางสายตา ผู้ที่เคลื่อนไหวไม่สะดวกที่ต้องใช้คีย์บอร์ดนำทาง และผู้ใช้งานอุปกรณ์สวิตช์
2. **Performance มอบโดย Tailwind CSS v4 & Zero Runtime**: ไม่มี CSS-in-JS Runtime Engine (ไม่ต้องประมวลผล CSS ใน JavaScript thread ระหว่างผู้ใช้เปิดเว็บ), ไม่ต้องโหลดคอมโพเนนต์ส่วนเกินจาก NPM, และมีขนาด Production Bundle ที่เล็กกว่าคู่แข่งอย่าง MUI หรือ Ant Design ถึง 4-8 เท่า

## 2. หลักการเบื้องหลัง (Under the Hood)

### 1. Radix UI จัดการ WAI-ARIA ให้เราอย่างไร?
- **Focus Management**:
  - เมื่อเปิด Dialog หรือ Menu โฟกัสจะไม่หลุดออกนอกขอบเขต (Focus Trap)
  - เมื่อกดปิด โฟกัสจะถูกคืนกลับไปยังจุดเริ่มต้น (Focus Restoration)
- **Keyboard Navigation Complexities**:
  - จัดการลำดับคีย์ตามสเปก เช่น เมนูแนวนอนใช้ลูกศรซ้าย-ขวา เมนูแนวตั้งใช้ลูกศรขึ้น-ลง การกดปุ่มตัวอักษรเพื่อค้นหารายการ (Typeahead)
- **Dynamic Screen Reader Updates**:
  - อัปเดตสถานะ เช่น `aria-expanded="true"`, `aria-selected="true"`, `aria-checked="true"`, และสร้าง Accessible Name อัตโนมัติ

### 2. เปรียบเทียบ Bundle Size: shadcn vs Monolithic UI Libraries

| ปัจจัยเปรียบเทียบ | Material UI (MUI v6) | Ant Design (AntD v5) | shadcn/ui (Radix + Tailwind v4) |
| :--- | :--- | :--- | :--- |
| **CSS Runtime Engine** | มี (Emotion / Pigment) | มี (@ant-design/cssinjs) | **ไม่มี (Zero Runtime CSS)** |
| **น้ำหนักปุ่ม Button เดี่ยว** | ~45 - 70 KB (Gzipped) | ~60 - 90 KB (Gzipped) | **~3 - 6 KB (Gzipped)** |
| **Tree-shaking Efficiency** | เสี่ยงหลุดทั้ง Theme Engine | เสี่ยงหลุด Global Utilities | **ตัดออกเกลี้ยง 100% (On-Demand Code)** |
| **Interaction to Next Paint (INP)** | มี overhead จาก CSS parsing | มี overhead จาก theme context | **ตอบสนองระดับ Sub-millisecond** |

## 3. ตัวอย่างโค้ด (TypeScript / TSX)

### ตัวอย่าง: หน้าต่างค้นหาคำสั่งด่วน (Accessible Command Palette Modal)

คอมโพเนนต์นี้แสดงการผสมผสาน Accessible Dialog, Focus Management, ARIA Combobox Spec และประสิทธิภาพการโหลดสูงสุด

```tsx filename="components/AccessibleCommandPalette.tsx"
"use client";

import * as React from "react";
import {
  Dialog,
  DialogContent,
  DialogDescription,
  DialogHeader,
  DialogTitle,
} from "@/components/ui/dialog";
import { Input } from "@/components/ui/input";
import { Search, Server, FileText, Settings, ArrowRight } from "lucide-react";

interface CommandItem {
  id: string;
  title: string;
  category: string;
  icon: React.ElementType;
}

const commands: CommandItem[] = [
  { id: "1", title: "สร้างเซิร์ฟเวอร์คลัสเตอร์ใหม่", category: "Infrastructure", icon: Server },
  { id: "2", title: "ดูบันทึกเหตุการณ์ความปลอดภัย (Audit Logs)", category: "Security", icon: FileText },
  { id: "3", title: "ตั้งค่านโยบายรหัสผ่านองค์กร", category: "Settings", icon: Settings },
];

export function AccessibleCommandPalette() {
  const [open, setOpen] = React.useState(false);
  const [query, setQuery] = React.useState("");
  const [activeIndex, setActiveIndex] = React.useState(0);

  // ดักจับคีย์ลัด Cmd+K หรือ Ctrl+K ในระดับระบบ
  React.useEffect(() => {
    function handleKeyDown(e: KeyboardEvent) {
      if ((e.metaKey || e.ctrlKey) && e.key === "k") {
        e.preventDefault();
        setOpen((prev) => !prev);
      }
    }
    window.addEventListener("keydown", handleKeyDown);
    return () => window.removeEventListener("keydown", handleKeyDown);
  }, []);

  const filteredCommands = commands.filter((cmd) =>
    cmd.title.toLowerCase().includes(query.toLowerCase())
  );

  return (
    <Dialog open={open} onOpenChange={setOpen}>
      <DialogContent className="p-0 overflow-hidden sm:max-w-xl border-border shadow-2xl">
        <DialogHeader className="sr-only">
          {/* Accessible Header บังคับตามมาตรฐาน WAI-ARIA แต่ซ่อนจากสายตา */}
          <DialogTitle>ค้นหาคำสั่งลัดระบบ (Command Palette)</DialogTitle>
          <DialogDescription>
            พิมพ์คำค้นหาเพื่อเปิดใช้งานฟีเจอร์หรือการตั้งค่าต่างๆ ในระบบอย่างรวดเร็ว
          </DialogDescription>
        </DialogHeader>

        {/* Input Bar with Search Icon */}
        <div className="flex items-center px-4 border-b border-border bg-card">
          <Search className="w-4 h-4 text-muted-foreground mr-2 shrink-0" aria-hidden="true" />
          <Input
            value={query}
            onChange={(e) => {
              setQuery(e.target.value);
              setActiveIndex(0);
            }}
            placeholder="พิมพ์ค้นหาคำสั่ง หรือหน้าจอที่ต้องการ..."
            className="border-0 focus-visible:ring-0 shadow-none text-base h-12 bg-transparent"
            role="combobox"
            aria-expanded={filteredCommands.length > 0}
            aria-controls="command-list"
            aria-autocomplete="list"
          />
        </div>

        {/* Result List with Full ARIA Listbox Navigation */}
        <div
          id="command-list"
          role="listbox"
          aria-label="รายการคำสั่งลัด"
          className="max-h-72 overflow-y-auto p-2 space-y-1"
        >
          {filteredCommands.length === 0 ? (
            <div className="py-8 text-center text-sm text-muted-foreground">
              ไม่พบคำสั่งที่ตรงกับ "{query}"
            </div>
          ) : (
            filteredCommands.map((item, index) => {
              const Icon = item.icon;
              const isSelected = index === activeIndex;
              return (
                <div
                  key={item.id}
                  role="option"
                  aria-selected={isSelected}
                  onClick={() => setOpen(false)}
                  onMouseEnter={() => setActiveIndex(index)}
                  className={`flex items-center justify-between px-3 py-2.5 rounded-xl text-sm cursor-pointer transition-colors ${
                    isSelected
                      ? "bg-primary text-primary-foreground font-medium"
                      : "hover:bg-accent hover:text-accent-foreground text-foreground"
                  }`}
                >
                  <div className="flex items-center gap-3">
                    <Icon className="w-4 h-4 shrink-0" aria-hidden="true" />
                    <span>{item.title}</span>
                  </div>
                  <span
                    className={`text-xs ${
                      isSelected ? "text-primary-foreground/80" : "text-muted-foreground"
                    }`}
                  >
                    {item.category}
                  </span>
                </div>
              );
            })
          )}
        </div>

        {/* Footer Shortcut Hints */}
        <div className="flex items-center justify-between px-4 py-2 bg-muted/40 border-t border-border text-[11px] text-muted-foreground">
          <span>กด <kbd className="px-1.5 py-0.5 rounded border bg-background font-mono">↑</kbd> <kbd className="px-1.5 py-0.5 rounded border bg-background font-mono">↓</kbd> เพื่อเลือก</span>
          <span>กด <kbd className="px-1.5 py-0.5 rounded border bg-background font-mono">ESC</kbd> เพื่อปิด</span>
        </div>
      </DialogContent>
    </Dialog>
  );
}
```

## 4. ผิด vs ถูก

| รูปแบบที่ผิด (Anti-Pattern) | รูปแบบที่ถูกต้อง (Best Practice) |
| :--- | :--- |
| **ลบ `DialogTitle` ทิ้งเพราะคิดว่าดีไซเนอร์ไม่ได้วาดหัวข้อมา**<br/>ผลลัพธ์: Console ฟ้อง Warning และ Screen Reader ไม่สามารถประกาศชื่อหน้าต่างที่เพิ่งเปิดขึ้นมาได้ | **ใส่ `DialogTitle` เสมอ และซ่อนด้วยคลาส `sr-only`**<br/>เพื่อให้ผู้ใช้ทั่วไปไม่เห็น แต่ผู้พิการทางสายตารู้ได้ทันทีว่าคือหน้าต่างอะไร |
| **ใช้คู่สีที่ Contrast ต่ำ เช่น ตัวหนังสือสีเทาอ่อนบนพื้นขาว**<br/>`<p className="text-gray-300 bg-white">ข้อความสำคัญ</p>`<br/>ผลลัพธ์: ตกเกณฑ์ WCAG 2.1 AA (Contrast Ratio ต่ำกว่า 4.5:1) | **ใช้คู่ Semantic Tokens ที่ทดสอบคอนทราสต์แล้ว**<br/>`text-muted-foreground bg-background` ผ่านเกณฑ์การอ่านได้ชัดเจนทุกอุปกรณ์ |
| **ติดตั้งไลบรารี UI ขนาดใหญ่หลายร้อยกิโลไบต์เข้ามาในโปรเจกต์**<br/>เพิ่มเวลา TBT (Total Blocking Time) และทำให้ผู้ใช้บนมือถือเปิดหน้าเว็บช้า | **ใช้ shadcn/ui คัดลอกเฉพาะคอมโพเนนต์ที่ใช้**<br/>รักษาขนาด Bundle ปลายทางให้เพรียวบางที่สุด |

## 5. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้เมื่อ:
- **โปรเจกต์ที่ต้องผ่านการตรวจสอบตามกฎหมายด้าน Accessibility**: เช่น เว็บไซต์ของหน่วยงานรัฐ, ธนาคาร, หรือแพลตฟอร์มระดับสากลที่ต้องได้มาตรฐาน ADA หรือ European Accessibility Act
- **แอปพลิเคชันที่ให้ความสำคัญสูงสุดกับ Core Web Vitals**: เพื่อให้ได้คะแนน SEO สูงสุด และลดอัตรา Bounce Rate ของผู้ใช้งานบนมือถือ

### ไม่ควรใช้เมื่อ:
- **โปรเจกต์ต้นแบบด่วน (Hackathon Prototype)** ที่ไม่สนใจผู้พิการทางสายตาและไม่แคร์คะแนน Performance ชั่วคราว (แต่ก็ยังแนะนำ shadcn อยู่ดีเพราะขึ้นโครงได้รวดเร็ว)

## 6. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: ทำไม Radix UI ถึงบังคับว่าต้องมี `<DialogTitle>` อยู่ภายใน `<DialogContent>` เสมอ และหากดีไซน์ไม่ต้องการให้แสดงข้อความหัวข้อ คุณจะจัดการอย่างไร?
**แนวทางตอบ:**
1. **เหตุผลที่บังคับ (W3C WAI-ARIA Spec)**: ตามมาตรฐาน WAI-ARIA ข้อกำหนดของ Dialog/Modal บังคับว่าต้องมี **Accessible Name** เพื่อให้เครื่อง Screen Reader สามารถประกาศชื่อและเจตนาของหน้าต่างนั้นให้ผู้ใช้งานที่มองไม่เห็นทราบทันทีที่เปิดขึ้นมา โดย Radix จะผูก `aria-labelledby` ของหน้าต่างเข้ากับ ID ของ `DialogTitle` อัตโนมัติ
2. **วิธีการแก้ปัญหาเมื่อดีไซน์ไม่ต้องการให้เห็นตัวหนังสือ**:
   - เราไม่ควรลบแท็ก `<DialogTitle>` ออก
   - แต่ให้ใส่ Tailwind Utility คลาส **`className="sr-only"`** (Screen Reader Only)
   - คลาสนี้จะซ่อนข้อความจากสายตา แต่ยังคงโครงสร้าง DOM และ Accessible Tree ไว้อย่างสมบูรณ์แบบ 100%

### Q2: ในแง่ของ Web Performance (Core Web Vitals) สถาปัตยกรรมของ shadcn/ui มีข้อได้เปรียบเหนือ Material UI (MUI) อย่างไรบ้าง?
**แนวทางตอบ:**
1. **Zero Runtime CSS vs CSS-in-JS Engine**: MUI ต้องโหลด JavaScript Engine ของ Emotion หรือ Pigment เข้ามาประมวลผลคำนวณสไตล์ในขณะรันไทม์ ทำให้ Main Thread ทำงานหนัก และส่งผลเสียต่อคะแนน **Interaction to Next Paint (INP)** และ **Total Blocking Time (TBT)** ในขณะที่ shadcn ใช้ Tailwind CSS v4 ที่คอมไพล์เป็น Static CSS Classes ล่วงหน้า จึงมีค่า Runtime Overhead เป็นศูนย์
2. **Bundle Size และ Tree-Shaking**: shadcn วางเฉพาะโค้ดที่เราใช้งานจริงไว้ในโฟลเดอร์โปรเจกต์ และใช้ Radix UI แบบแยกแพ็กเกจ (Modular Primitives) ขนาด JavaScript ที่ส่งไปยังเบราว์เซอร์จึงเล็กกว่ามาก ช่วยปรับปรุงคะแนน **Largest Contentful Paint (LCP)** ให้เร็วขึ้นอย่างมหาศาล
