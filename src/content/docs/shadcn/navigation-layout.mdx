## 1. แนวคิด (Concept)

การจัดวางโครงสร้างหน้าจอ (Layout) และระบบนำทาง (Navigation) ถือเป็นกระดูกสันหลังของเว็บแอปพลิเคชันยุคใหม่ shadcn/ui เตรียมคอมโพเนนต์ที่ครอบคลุมทุกมิติของการจัดระเบียบข้อมูล:

1. **`Sidebar`**: ระบบเมนูด้านข้างที่สมบูรณ์แบบที่สุด รองรับการพับเก็บ (Collapsible), Floating mode, เมนูด้านในแบบจัดกลุ่ม (Groups & Sub-menus) และสลับเป็น Drawer บนสมาร์ตโฟนอัตโนมัติ
2. **`Tabs`**: การสลับมุมมองเนื้อหาในหน้าเดียวโดยไม่ต้องเปลี่ยน URL เหมาะสำหรับแยกหมวดข้อมูล เช่น "ภาพรวม" กับ "การตั้งค่า"
3. **`Accordion`**: รายการพับเก็บเนื้อหาเพื่อประหยัดพื้นที่หน้าจอ มักใช้ในหน้าคำถามที่พบบ่อย (FAQ) หรือตัวกรองขั้นสูง
4. **`Breadcrumb`**: แถบระบุเส้นทางตำแหน่งปัจจุบัน ช่วยให้ผู้ใช้เข้าใจว่ากำลังอยู่ในระดับชั้นใดของระบบ (e.g. หน้าแรก > คลังสินค้า > รายละเอียดสินค้า)
5. **`ScrollArea`**: แถบเลื่อน (Scrollbar) ที่ปรับแต่งสไตล์ได้ข้ามเบราว์เซอร์ ไม่บดบังเนื้อหา และดูเรียบหรูสม่ำเสมอกันทั้งบน Mac, Windows และ Linux

## 2. หลักการเบื้องหลัง (Under the Hood)

### 1. การทำงานของ shadcn `<SidebarProvider>`
- ระบบ Sidebar ใน shadcn/ui ใช้ React Context (`SidebarProvider`) เพื่อจัดการสถานะเปิด/ปิด (Open/Collapsed state)
- **Cookie Persistence**: เมื่อผู้ใช้กดปุ่มพับ Sidebar สถานะจะถูกบันทึกลงใน Browser Cookie ทำให้เมื่อรีเฟรชหน้าหรือย้ายหน้าใน Next.js เซิร์ฟเวอร์สามารถอ่านค่า Cookie นั้นและเรนเดอร์เลย์เอาต์ที่พับเก็บไว้ล่วงหน้าได้ทันที **ป้องกันปัญหาหน้าจอกระตุกขยายไปมา (Layout Shift on Hydration)**
- **Keyboard Shortcut**: ฝังคีย์ลัดระดับสากล เช่น `Cmd + B` หรือ `Ctrl + B` เพื่อสลับการเปิด/ปิด Sidebar ได้ทันที

### 2. Accessibility ใน `<Accordion>` และ `<Tabs>`
- Radix UI จัดการ ARIA Attributes ทั้งหมด:
  - `<TabsList>` มี `role="tablist"`
  - `<TabsTrigger>` มี `role="tab"` พร้อม `aria-selected`
  - รองรับการใช้แป้นพิมพ์ลูกศรซ้าย-ขวา เพื่อเลื่อนสลับแท็บโดยอัตโนมัติ (Arrow Navigation) ตามมาตรฐาน WAI-ARIA Tabs Design Pattern

## 4. ผิด vs ถูก

| รูปแบบที่ผิด (Anti-Pattern) | รูปแบบที่ถูกต้อง (Best Practice) |
| :--- | :--- |
| **ซ่อน Sidebar บนมือถือด้วยแค่ CSS `hidden md:flex`**<br/>ผลลัพธ์: ผู้ใช้บนมือถือไม่มีปุ่มเปิดเมนู หรือหากทำ Drawer เอง มักลืม Focus Trap ทำให้ผู้ใช้กดทะลุ | **ใช้ `<SidebarProvider>` ของ shadcn**<br/>ซึ่งมี Sheet Drawer สำหรับสมาร์ตโฟนในตัวโดยอัตโนมัติ และรองรับ a11y ครบถ้วน |
| **เก็บสถานะเปิด/ปิด Sidebar ไว้ใน LocalStorage ฝั่ง Client เพียงอย่างเดียว**<br/>ส่งผลให้เกิด Layout Shift ตอนหน้าเว็บโหลด เพราะ Server ส่งสถานะหนึ่งมา แต่ Client สลับเป็นอีกสถานะ | **ผูกสถานะกับ Browser Cookie**<br/>เซิร์ฟเวอร์สามารถอ่าน Cookie ล่วงหน้าแล้วเรนเดอร์ขนาด Sidebar ได้ถูกต้องตั้งแต่เฟรมแรก |
| **ใช้ Native `overflow-y-scroll` ที่มี Scrollbar สีเทาขนาดใหญ่ขัดตา**<br/>หน้าตาไม่สอดคล้องกับธีม โดยเฉพาะบนระบบ Windows | **ใช้ `<ScrollArea>`**<br/>แถบเลื่อนจะถูกซ่อนจนกว่าจะมีการเลื่อนเมาส์ และสีสันกลมกลืนกับ Theme Token |

## 5. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้เมื่อ:
- **แอปพลิเคชันระบบจัดการ (SaaS / Web App / Portal)**: ที่มีลำดับชั้นของหน้าและเมนูจำนวนมาก
- **หน้าตั้งค่าที่มีข้อมูลหลายหมวด**: ใช้ `Tabs` เพื่อจัดกลุ่ม ช่วยให้ผู้ใช้ไม่ต้องเลื่อนหน้าจอยาวเกินไป
- **Documentation & FAQ**: ใช้ `Accordion` เพื่อให้ผู้ใช้สามารถกวาดสายตาดูหัวข้อทั้งหมดได้ก่อนคลิกอ่านเนื้อหา

### ไม่ควรใช้เมื่อ:
- **Landing Page แบบหน้าเดียวสั้นๆ**: ที่มีปุ่มลิงก์เพียง 2-3 อัน ไม่จำเป็นต้องใช้ Sidebar หรือ Tabs ซับซ้อน
- **เนื้อหาตารางข้อมูลที่ต้องขยายแนวกว้างมากๆ**: การเปิด Sidebar ตลอดเวลาอาจกินพื้นที่การดูตาราง ควรตั้งค่า Sidebar ให้เป็นโหมด Collapsible

## 6. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: Accordion ใน shadcn/ui มีคุณสมบัติ Accessibility อะไรบ้างที่ทำให้ผู้พิการทางสายตาสามารถเข้าถึงเนื้อหาที่ซ่อนอยู่ได้?
**แนวทางตอบ:**
1. **ARIA Roles & States**: หัวข้อคำถามถูกห่อหุ้มด้วยแท็ก `<button>` ภายใน Header พร้อมคุณลักษณะ `aria-expanded="true/false"` เพื่อบอกว่าเนื้อหากำลังกางออกหรือพับเก็บอยู่
2. **`aria-controls` และ `id` Binding**: ตัวปุ่ม Trigger จะชี้ไปยัง ID ของเนื้อหา Panel ด้านล่างอย่างแม่นยำ
3. **Keyboard Interactivity**: ผู้ใช้สามารถใช้ปุ่ม `Enter` หรือ `Space` เพื่อเปิด/ปิด และใช้ปุ่มลูกศรขึ้น-ลงเพื่อเลื่อนไปยังหัวข้อถัดไปได้ทันที

### Q2: ในการสร้าง Dashboard ด้วย Next.js App Router ระบบ Sidebar ของ shadcn/ui ป้องกันปัญหา Layout Shift (CLS) ระหว่างการทำ Server-Side Rendering (SSR) อย่างไร?
**แนวทางตอบ:**
- shadcn Sidebar ใช้กลยุทธ์ **Cookie-based State Persistence**:
  - เมื่อผู้ใช้กด Toggle ยุบหรือขยาย Sidebar สคริปต์จะบันทึกสถานะลงใน Cookie ของเบราว์เซอร์
  - ในการร้องขอหน้าถัดไป Next.js Server Component ใน `layout.tsx` สามารถอ่านค่า Cookie นี้ผ่านฟังก์ชัน `cookies()` ของ Next.js
  - เซิร์ฟเวอร์จึงสามารถส่ง HTML ที่มีคลาสขยายหรือยุบของ Sidebar ที่ถูกต้องมาตั้งแต่แรก ทำให้ React ไม่ต้องมาคำนวณสลับเลย์เอาต์ใหม่ฝั่งเบราว์เซอร์ จึงตัดปัญหา Layout Shift และ Hydration Mismatch ได้อย่างสมบูรณ์
