# SQL vs NoSQL

หนึ่งในคำถามระดับคลาสสิกในการออกแบบสถาปัตยกรรมระบบ (System Design) คือ **"โปรเจกต์นี้ควรใช้ SQL หรือ NoSQL?"** ในยุคปัจจุบัน คำตอบของวิศวกรอาวุโสไม่ใช่การเลือกข้างใดข้างหนึ่งแบบสุดโต่งอีกต่อไป แต่คือการเข้าใจจุดแข็งและข้อจำกัดเชิงลึกของแต่ละเทคโนโลยี เพื่อนำมาประกอบกันอย่างลงตัว เอกสารฉบับนี้เจาะลึกการเปรียบเทียบสถาปัตยกรรมระหว่าง **SQL (PostgreSQL 16)** และ **NoSQL (MongoDB, Redis, Elasticsearch, SQLite)** พร้อมทฤษฎีบท **CAP Theorem** และเหตุผลทางวิศวกรรมว่าทำไมระบบร้านค้าเนื้อพรีเมียม **Smart Butcher Marketplace** จึงเลือกใช้ **PostgreSQL 16 เป็นฐานข้อมูลหลักควบคู่กับ Redis (Polyglot Persistence)**

| หัวข้อในหน้านี้ | สาระสำคัญ |
| :--- | :--- |
| **1. เปรียบเทียบสถาปัตยกรรม SQL (Relational) vs NoSQL (Non-Relational)** | โครงสร้างตาราง vs เอกสาร/คีย์-แวลู, ACID vs BASE, การขยายตัว (Scale-up vs Scale-out) และการใช้ `JSONB` ใน PostgreSQL 16 |
| **2. เมื่อไหร่ควรเลือกใช้ MongoDB (Document Database)** | โมเดล BSON Document, การฝังข้อมูล (Embedding vs Referencing) และกรณีศึกษา IoT Cold-Chain Sensor Logs |
| **3. การใช้ Redis สำหรับ Caching, Session, Queue และ Rate Limiting** | โครงสร้างข้อมูลในหน่วยความจำ (In-Memory), รูปแบบ Cache-Aside Pattern และ Token Bucket Rate Limiting |
| **4. ฐานข้อมูลเฉพาะทางที่ควรรู้จัก (SQLite, Elasticsearch) และทฤษฎีบท CAP Theorem** | การทำงานของ Inverted Index, Embedded DB และการวิเคราะห์ CP vs AP เมื่อเกิด Network Partition |
| **5. แนวคิด Polyglot Persistence และเหตุผลที่ระบบร้านค้าเลือก PostgreSQL 16** | การผสาน PostgreSQL 16 + Redis ในระบบเดียว และทำไมระบบตัดสต็อกและคิดเงินจึงห้ามสูญเสีย ACID |

<Callout type="tip" title="คำจำกัดความที่แท้จริงของคำว่า NoSQL ในยุคปัจจุบัน">
คำว่า **NoSQL** ในทางวิศวกรรมสมัยใหม่ไม่ได้แปลว่า "No SQL (ห้ามใช้ SQL)" แต่ย่อมาจาก **"Not Only SQL (ไม่ได้มีแค่ตารางเชิงสัมพันธ์เพียงอย่างเดียว)"** และในทางกลับกัน ฐานข้อมูลอย่าง **PostgreSQL 16** ก็ได้พัฒนาชนิดข้อมูล **`JSONB`** พร้อมดัชนี **GIN Index** จนสามารถจัดเก็บและค้นหาข้อมูลกึ่งโครงสร้าง (Semi-structured Document) ได้เร็วเทียบเท่าหรือเหนือกว่าฐานข้อมูล NoSQL หลายตัวภายใต้ร่มเงาของ ACID Transaction เดียวกัน!
</Callout>
