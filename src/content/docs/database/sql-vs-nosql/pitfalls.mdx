## 1. ข้อผิดพลาดที่พบบ่อย (Anti-patterns)

1. **การเลือกใช้ฐานข้อมูลที่ไม่มี ACID หรือไม่ทำ Transaction กับระบบการเงินและสต็อกสินค้า**
   - **สาเหตุ:** เลือกฐานข้อมูลตามกระแสโดยไม่วิเคราะห์ความต้องการด้านความถูกต้องของข้อมูล (Consistency)
   - **ผลกระทบ:** เกิดปัญหาตัดสต็อกซ้ำซ้อน (Overselling) หรือตัดเงินลูกค้าสำเร็จแต่ใบสั่งซื้อไม่ถูกสร้าง
   - **วิธีแก้:** ใช้ PostgreSQL 16 พร้อมกลไก ACID Transaction สำหรับข้อมูลหลักทางธุรกิจเสมอ

2. **การยัดข้อมูลทุกอย่างลงในคอลัมน์ `JSONB` ก้อนเดียวใน PostgreSQL**
   - **สาเหตุ:** ขี้เกียจออกแบบตารางและรัน Migration เลยสร้างตารางที่มีแค่ `id` กับ `data JSONB`
   - **ผลกระทบ:** สูญเสียการตรวจสอบชนิดข้อมูล การบังคับ `NOT NULL` การเชื่อม Foreign Key และทำให้สถิติของ Query Planner เพี้ยน
   - **วิธีแก้:** แยกฟิลด์หลักที่มีโครงสร้างแน่นอนออกเป็นคอลัมน์ปกติ แล้วใช้ `JSONB` เฉพาะกับข้อมูลส่วนขยายที่มีโครงสร้างหลากหลายเท่านั้น

3. **การฝัง Array ที่เติบโตไปเรื่อยๆ ลงในเอกสารใบเดียวของ MongoDB (Unbounded Array)**
   - **สาเหตุ:** นำทุกคำสั่งซื้อหรือทุกคอมเมนต์มา `push` ต่อท้ายในเอกสารของ `user` หรือ `product`
   - **ผลกระทบ:** เมื่อข้อมูลโตเกินขีดจำกัด **16 MB ต่อเอกสาร** การบันทึกข้อมูลจะพังทันทีและทำให้ประสิทธิภาพการเขียนตกต่ำ
   - **วิธีแก้:** แยกข้อมูลที่เติบโตแบบไร้ขีดจำกัดออกเป็น Collection แยกแล้วอ้างอิงด้วย ID

4. **การใช้คำสั่ง `KEYS *` บน Redis ในสภาพแวดล้อม Production**
   - **สาเหตุ:** ต้องการค้นหาและลบคีย์แคชที่มีคำนำหน้าเหมือนกันทั้งหมดด้วยวิธีง่ายๆ
   - **ผลกระทบ:** เนื่องจาก Redis ทำงานด้วย Single-threaded Event Loop คำสั่ง `KEYS *` จะบล็อกเธรดหลักเพื่อกวาดอ่านคีย์ทั้งหมดใน RAM ทำให้คำขออื่นๆ ทั้งระบบค้างและเกิด Timeout
   - **วิธีแก้:** ใช้คำสั่ง `SCAN` ที่ทยอยดึงคีย์ทีละส่วนโดยไม่บล็อกระบบ หรือเก็บชื่อคีย์ที่เกี่ยวข้องไว้ในโครงสร้าง `SET`

5. **การตั้งฐานข้อมูลแยกหลายตัวตั้งแต่เริ่มโปรเจกต์โดยไม่มีความจำเป็น (Premature Polyglot Sprawl)**
   - **สาเหตุ:** พยายามใช้ฐานข้อมูล 4-5 ยี่ห้อในระบบขนาดเล็กที่มีผู้ใช้งานหลักพันคน
   - **ผลกระทบ:** เสียค่าเซิร์ฟเวอร์สูงมาก เสียเวลาเขียนโค้ดซิงค์ข้อมูลข้ามฐานข้อมูล และเมื่อเกิดปัญหาข้อมูลไม่ตรงกันจะแก้ไขได้ยากมาก
   - **วิธีแก้:** ใช้ขีดความสามารถของ PostgreSQL 16 ให้เต็มที่ก่อน แล้วเพิ่ม Redis หรือฐานข้อมูลเฉพาะทางเมื่อมีคอขวดที่ชัดเจน

## 2. Checklist สรุป

แนวทางตรวจสอบการออกแบบสถาปัตยกรรมฐานข้อมูลสำหรับระบบ **Smart Butcher Marketplace**:

- [ ] **System of Record on PostgreSQL 16:** ตารางหลักที่ต้องการความถูกต้องสูงสุด (`users`, `categories`, `products`, `orders`, `order_items`, `payments`) อยู่บน PostgreSQL 16 พร้อม Foreign Keys และ ACID Transactions
- [ ] **Smart JSONB Usage:** ใช้คอลัมน์ `JSONB` คู่กับ `GIN Index` สำหรับข้อมูลคุณลักษณะเสริมที่ยืดหยุ่น โดยไม่นำมาปนกับคอลัมน์หลักที่ใช้คำนวณเงินหรือเชื่อมตาราง
- [ ] **Redis Cache-Aside with TTL:** ข้อมูลแค็ตตาล็อกที่ถูกอ่านซ้ำบ่อยๆ มีการแคชไว้ใน Redis พร้อมกำหนดเวลาหมดอายุ (`EX`) ทุกคีย์ และมีการสั่ง `DEL` ล้างแคชหลังจบการแก้ไขข้อมูล
- [ ] **Post-Commit Side Effects:** การล้างแคชใน Redis หรือการส่งงานเข้า Queue ถูกเรียกทำงาน **หลังจาก** ที่บล็อก `prisma.$transaction` ทำการ `COMMIT` สำเร็จแล้วเท่านั้น
- [ ] **Zero Blocking Redis Commands:** ในโค้ด Production ไม่มีการเรียกใช้คำสั่ง `KEYS *` บน Redis เด็ดขาด
- [ ] **Right Tool for Media:** ไฟล์รูปภาพและเอกสารขนาดใหญ่ถูกจัดเก็บใน Object Storage (S3 / Supabase Storage / R2) แยกออกจากฐานข้อมูล

## 3. ลำดับการเรียนที่แนะนำ และ ดูเพิ่มเติมที่

ยินดีด้วย! คุณได้เรียนรู้เนื้อหาในหมวด **DATABASE** ครบถ้วนตั้งแต่สถาปัตยกรรมภายในของ PostgreSQL 16, การออกแบบตาราง, การทำ Indexing, การจัดการ Concurrency/Transactions, การทำ Migration, การสำรองข้อมูล, ความปลอดภัย ไปจนถึงการผสานการทำงานกับ NoSQL และ Redis ขอแนะนำให้ศึกษาเชื่อมโยงไปยังฝั่ง **BACKEND** เพื่อนำฐานข้อมูลไปประกอบร่างเป็นระบบที่สมบูรณ์:

<Callout type="tip" title="เส้นทางการศึกษาต่อเพื่อเชื่อมต่อ Database เข้ากับ Backend Architecture">
1. **การทบทวนรากฐานของ PostgreSQL 16 และการออกแบบโครงสร้างตาราง:**  
   👉 **[PostgreSQL 16](/docs/database/postgresql)** และ **[Database Design](/docs/database/database-design)** — ทบทวนโครงสร้าง ERD ทั้ง 6 ตารางของระบบ Smart Butcher Marketplace และการใช้ชนิดข้อมูลขั้นสูง

2. **การจัดการธุรกรรมและการป้องกันปัญหาการแย่งชิงข้อมูล:**  
   👉 **[Transactions](/docs/database/transactions)** และ **[Concurrency](/docs/database/concurrency)** — เจาะลึกการทำงานของ ACID, Isolation Levels และการล็อกแถวข้อมูลตอนตัดสต็อกสินค้า

3. **การพัฒนาแอปพลิเคชัน Backend เชื่อมต่อฐานข้อมูลระดับ Production:**  
   👉 **[Prisma ORM](/docs/backend/prisma-orm)**, **[NestJS](/docs/backend/nestjs)** และ **[Docker](/docs/backend/docker)** — เรียนรู้การวางโครงสร้างโค้ด Backend, การทำ Dependency Injection และการรันระบบทั้งหมดด้วย Docker Compose
</Callout>
