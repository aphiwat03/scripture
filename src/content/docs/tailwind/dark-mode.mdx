## 1. แนวคิด (Concept)

ระบบ **Dark Mode** ในเว็บแอปพลิเคชันยุคใหม่ไม่ใช่แค่ลูกเล่นตกแต่ง แต่เป็นมาตรฐานสำคัญที่ช่วยลดความเมื่อยล้าของสายตาและประหยัดพลังงานบนหน้าจอ OLED

ใน **Tailwind CSS v4** ร่วมกับ **Next.js 16 App Router**:
- การตั้งค่า Dark Mode ถูกย้ายจากไฟล์ JavaScript เก่า (`darkMode: 'class'`) มาสู่การใช้ Directive สากล **`@custom-variant`** ในไฟล์ CSS โดยตรง
- ผสานการทำงานร่วมกับ **`next-themes`** เพื่อจัดการการสลับโหมด (Light, Dark, System) ได้อย่างไร้รอยต่อ
- ป้องกันปัญหาภาพกระพริบขาว (Flash of Unstyled Theme - FOUT) หรือ Hydration Mismatch ใน Next.js ด้วยแนวปฏิบัติที่ถูกต้อง

## 2. หลักการเบื้องหลัง (Under the Hood)

### กลไก `@custom-variant dark` และ Semantic CSS Variables
1. **The Modern Custom Variant Definition**:
   ใน `globals.css` เราประกาศ:
   ```css
   @custom-variant dark (&:where(.dark, .dark *));
   ```
   - ฟังก์ชัน `:where()` ช่วยให้ Selector มีค่าความสำคัญ (**Specificity**) เท่ากับ `0` ทำให้ Utility Classes ทั่วไปสามารถ override หรือ override ตัวเองได้อย่างราบรื่นโดยไม่เกิด Specificity War
2. **Semantic Token Mapping ผ่าน `@theme`**:
   แทนที่จะเขียน `dark:bg-neutral-900 dark:text-white` ซ้ำไปซ้ำมาในทุกปุ่มและทุกกล่อง แนวทางที่ดีที่สุดคือการกำหนด **Semantic Tokens** ใน `:root` และ `html.dark`:
   ```css
   :root {
     --bg-canvas: #ffffff;
     --text-primary: #171717;
   }
   html.dark {
     --bg-canvas: #0a0a0a;
     --text-primary: #ededed;
   }
   @theme inline {
     --color-canvas: var(--bg-canvas);
     --color-foreground: var(--text-primary);
   }
   ```
   ทำให้เปลี่ยนสีทั้งระบบได้ผ่านการเปลี่ยนคลาสที่แท็ก `<html>` เพียงจุดเดียว!

## 3. ตัวอย่างโค้ด (Tailwind v4 & TSX)

### ตัวอย่างที่ 1: การติดตั้ง `next-themes` และปุ่มสลับธีม (ThemeToggle ใน Next.js 16)

```tsx filename="src/components/ThemeProvider.tsx"
"use client";

import { ThemeProvider as NextThemesProvider } from "next-themes";
import type { ComponentProps } from "react";

export function ThemeProvider({
  children,
  ...props
}: ComponentProps<typeof NextThemesProvider>) {
  return (
    <NextThemesProvider
      attribute="class"
      defaultTheme="system"
      enableSystem
      disableTransitionOnChange
      {...props}
    >
      {children}
    </NextThemesProvider>
  );
}
```

```tsx filename="src/components/ThemeToggle.tsx"
"use client";

import { useTheme } from "next-themes";
import { useEffect, useState } from "react";
import { Sun, Moon, Monitor } from "lucide-react";

export function ThemeToggle() {
  const [mounted, setMounted] = useState(false);
  const { theme, setTheme } = useTheme();

  // ป้องกัน Hydration mismatch ระหว่าง Server และ Client
  useEffect(() => {
    setMounted(true);
  }, []);

  if (!mounted) {
    return (
      <div className="size-9 rounded-xl border border-neutral-200 bg-neutral-100/50 dark:border-neutral-800 dark:bg-neutral-800/50" />
    );
  }

  return (
    <div className="flex items-center rounded-xl border border-neutral-200 bg-neutral-100 p-1 dark:border-neutral-800 dark:bg-neutral-900">
      <button
        type="button"
        onClick={() => setTheme("light")}
        aria-label="ธีมสว่าง"
        className={`flex size-7 items-center justify-center rounded-lg transition-all ${
          theme === "light"
            ? "bg-white text-amber-600 shadow-xs"
            : "text-neutral-500 hover:text-neutral-900 dark:text-neutral-400"
        }`}
      >
        <Sun className="size-4" />
      </button>

      <button
        type="button"
        onClick={() => setTheme("dark")}
        aria-label="ธีมมืด"
        className={`flex size-7 items-center justify-center rounded-lg transition-all ${
          theme === "dark"
            ? "bg-neutral-800 text-indigo-400 shadow-xs"
            : "text-neutral-500 hover:text-neutral-900 dark:text-neutral-400"
        }`}
      >
        <Moon className="size-4" />
      </button>

      <button
        type="button"
        onClick={() => setTheme("system")}
        aria-label="อิงตามระบบปฏิบัติการ"
        className={`flex size-7 items-center justify-center rounded-lg transition-all ${
          theme === "system"
            ? "bg-white text-neutral-800 shadow-xs dark:bg-neutral-800 dark:text-white"
            : "text-neutral-500 hover:text-neutral-900 dark:text-neutral-400"
        }`}
      >
        <Monitor className="size-4" />
      </button>
    </div>
  );
}
```

## 4. เทียบกับ CSS ปกติ

| งาน | Tailwind v4 Architecture | Pure Native CSS Equivalent |
| :--- | :--- | :--- |
| **Custom Variant** | `@custom-variant dark (&:where(.dark, .dark *));` | `.dark .my-element, .dark * .my-element` |
| **Dark Class บน Element** | `dark:bg-neutral-950 dark:text-white` | `.dark .element { background-color: #0a0a0a; color: #fff; }` |
| **CSS Variables Theming** | `bg-(--color-canvas)` ที่สลับค่าใน CSS | `:root { --bg: #fff; } html.dark { --bg: #000; }` |
| **Auto Preference** | ตรวจจับผ่าน `next-themes` หรือ `@media (prefers-color-scheme)` | `@media (prefers-color-scheme: dark) { :root { ... } }` |

## 5. ผิด vs ถูก

### จุดที่ 1: ลืมใส่ `suppressHydrationWarning` บนแท็ก `<html>` ใน Next.js Root Layout
```tsx
// ❌ ผิด: ก่อให้เกิด Hydration Error คอนโซลแดงใน Next.js 16 เมื่อ next-themes แปะคลาส dark
<html lang="th">
  <body>{children}</body>
</html>

// ✅ ถูก: ใส่ suppressHydrationWarning ที่แท็ก html
<html lang="th" suppressHydrationWarning>
  <body>{children}</body>
</html>
```
*เหตุผล*: `next-themes` มีการรัน inline script เล็กๆ ก่อนที่ React จะ hydrate เพื่อแปะคลาส `.dark` ลงบนแท็ก `<html>` ตามค่าใน localStorage หากไม่มี `suppressHydrationWarning` ตัว React 19 จะฟ้องว่า HTML บน Server ไม่ตรงกับ Client

### จุดที่ 2: พยายามสร้าง `tailwind.config.js` เพื่อกำหนด `darkMode: 'class'` ใน v4
```javascript
// ❌ ผิด: รูปแบบเดิมของ Tailwind v3 ซึ่งถูกยกเลิกใน v4
module.exports = {
  darkMode: 'class',
}

// ✅ ถูก: ประกาศ @custom-variant ใน globals.css
@import "tailwindcss";
@custom-variant dark (&:where(.dark, .dark *));
```
*เหตุผล*: Tailwind v4 เป็นสถาปัตยกรรม CSS-first การควบคุม Variant ทั้งหมดทำผ่าน CSS Directives

## 6. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้
- รวมกับ `next-themes` ใน Next.js 16 สำหรับเว็บไซต์ที่ต้องการให้ผู้ใช้เลือกสลับ Light/Dark ได้เอง และจดจำค่าใน LocalStorage
- ใช้ CSS Variables (`--color-canvas`, `--color-ink`) ร่วมกับ `@theme` สำหรับโปรเจกต์ระดับองค์กร เพื่อหลีกเลี่ยงการเขียน `dark:` กระจายเต็มโค้ด

### ไม่ควรใช้
- ไม่ควรสลับฟอนต์หรือเปลี่ยนขนาด padding/margin เมื่อสลับ Dark Mode เพราะจะทำให้หน้าเว็บขยับสั่น ควรเปลี่ยนเฉพาะคุณสมบัติด้านสี (Color, Background, Border, Shadow) เท่านั้น

## 7. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: ทำไมใน Tailwind v4 การประกาศ Dark Mode Variant จึงนิยมใช้ `:where(.dark, .dark *)`?
**แนวทางคำตอบ**: 
เนื่องจากฟังก์ชัน `:where()` ใน CSS มีคุณสมบัติพิเศษคือ **มีค่า Specificity เท่ากับศูนย์ (Zero Specificity)** การประกาศ `&:where(.dark, .dark *)` ทำให้ Selector ของ dark variant ไม่ไปเพิ่มคะแนนความสำคัญของคลาส ส่งผลให้นักพัฒนาสามารถใช้ Utility Classes อื่นๆ เขียน override สไตล์ได้อย่างเป็นธรรมชาติและไม่มีปัญหาเรื่องคลาสชนกันจนสไตล์ไม่ยอมเปลี่ยน

### Q2: จะป้องกันปัญหา Flash of Incorrect Theme (หน้าจอขาววาบก่อนเข้า Dark Mode) ใน Next.js App Router ได้อย่างไร?
**แนวทางคำตอบ**: 
ปัญหาเกิดจากการรอให้ React โค้ดรันบนฝั่ง Client ก่อนจึงจะรู้ว่าผู้ใช้เลือก Dark Mode ไว้ ส่งผลให้เบราว์เซอร์เรนเดอร์ธีมสว่างไปก่อน วิธีป้องกันคือการใช้ไลบรารีอย่าง `next-themes` ซึ่งจะแทรก Inline Script ขนาดจิ๋วแบบบล็อกกิ้งเข้าไปที่ส่วนหัวของ HTML เพื่ออ่านค่าจาก `localStorage` หรือ `matchMedia` และแทรกคลาส `.dark` ลงในแท็ก `<html>` ก่อนที่เบราว์เซอร์จะเริ่มวาดหน้าจอ (Paint) พร้อมทั้งใส่ `suppressHydrationWarning` บน `<html>` เพื่อไม่ให้ React ฟ้องเตือน
