## 1. แนวคิด (Concept)

การสร้างเว็บที่รองรับทุกขนาดหน้าจอใน Tailwind CSS ยึดปรัชญา **Mobile-First Breakpoint System**:
- คลาสที่ไม่มี Prefix (เช่น `p-4 text-base`) มีผลกับ **หน้าจอขนาดเล็กที่สุด (มือถือ)** เป็นค่าเริ่มต้น
- Breakpoint Prefixes (`sm:`, `md:`, `lg:`, `xl:`, `2xl:`) ทำงานผ่านเงื่อนไข `min-width` หมายถึง "ตั้งแต่ขนาดนี้ขึ้นไป"

และใน Tailwind CSS v4 ฟีเจอร์ที่ปฏิวัติวงการ Front-end คือ **Native Container Queries (`@container`)**:
- สื่อสารกับขนาดของ **ตัวคอนเทนเนอร์แม่ (Parent Box)** โดยตรง แทนที่จะพึ่งพาขนาดหน้าต่างบราวเซอร์ (Viewport)
- ช่วยให้คอมโพเนนต์ชิ้นเดียวกัน เช่น `<ProductCard />` สามารถแสดงผลแบบแนวนอนเมื่ออยู่ในหน้าหลัก (กว้าง) และสลับเป็นแนวตั้งเมื่อถูกนำไปวางใน Sidebar (แคบ) ได้อัตโนมัติ

## 2. หลักการเบื้องหลัง (Under the Hood)

### กลไก Mobile-First Media Queries และ CSS Container Queries
1. **Breakpoint Scale (`min-width`)**:
   - `sm:` -> `@media (min-width: 640px)`
   - `md:` -> `@media (min-width: 768px)`
   - `lg:` -> `@media (min-width: 1024px)`
   - `xl:` -> `@media (min-width: 1280px)`
   - `2xl:` -> `@media (min-width: 1536px)`
2. **Container Queries ใน v4 Engine**:
   - เมื่อใส่ `@container` บนกล่องแม่ Oxide Engine จะกำหนด:
     ```css
     container-type: inline-size;
     ```
   - เมื่อใส่ `@md:flex-row` บนตัวลูก จะถูกแปลงเป็น:
     ```css
     @container (min-width: 28rem /* 448px */) {
       .adaptive-card { flex-direction: row; }
     }
     ```
   ทำให้คอมโพเนนต์เป็นอิสระจาก Viewport อย่างสมบูรณ์ (Truly Modular Component)

## 4. เทียบกับ CSS ปกติ

| งาน | Tailwind v4 Utility | Pure CSS เทียบเท่า |
| :--- | :--- | :--- |
| **ซ่อนในมือถือ แสดงใน Tablet** | `hidden md:block` | `@media (min-width: 768px) { display: block; }` |
| **Grid ขยายตามเบรกพอยต์** | `grid-cols-1 md:grid-cols-3` | `@media (min-width: 768px) { grid-template-columns: repeat(3, 1fr); }` |
| **สร้างขอบเขต Container** | `@container` | `container-type: inline-size;` |
| **เปลี่ยนทิศทางตามขนาดกล่องแม่** | `@md:flex-row` | `@container (min-width: 28rem) { flex-direction: row; }` |

## 5. ผิด vs ถูก

### จุดที่ 1: การคิดแบบ Desktop-First (เขียนสไตล์จอใหญ่แล้วพยายามลบล้างในมือถือ)
```tsx
// ❌ ผิด: พยายามคิดจากจอใหญ่ แล้วใช้ sm: เป็นจอมือถือ (ซึ่งเข้าใจผิด)
<div className="flex-row sm:flex-col">

// ✅ ถูก: คิดแบบ Mobile-First โดยให้ค่าตั้งต้นเป็นจอมือถือ แล้วขยายด้วย sm: หรือ md:
<div className="flex-col sm:flex-row">
```
*เหตุผล*: Breakpoints ของ Tailwind ทั้งหมดเป็น `min-width` เสมอ คลาสที่ไม่มี prefix คือขนาดเล็กสุด เมื่อหน้าจอกว้างขึ้นเรื่อยๆ ถึงจะ activate คลาสที่มี prefix

### จุดที่ 2: ใช้ Container Query Variant โดยลืมประกาศ `@container` บน Container แม่
```tsx
// ❌ ผิด: ใส่ @md:flex-row บนคอมโพเนนต์ลูก แต่ลืมใส่ @container ที่ตัวแม่
<div>
  <div className="@md:flex-row">...</div>
</div>

// ✅ ถูก: ต้องมี @container บนองค์ประกอบแม่ เพื่อสร้าง Container Context
<div className="@container">
  <div className="@md:flex-row">...</div>
</div>
```
*เหตุผล*: CSS Container Queries ต้องการให้มี Element บรรพบุรุษที่ถูกระบุ `container-type: inline-size` หากไม่มี เบราว์เซอร์จะไม่สามารถประเมินขนาดกล่องเพื่อ trigger variant `@md:` ได้

## 6. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้ Media Query Breakpoints (`sm:`, `md:`, `lg:`)
- การควบคุม Page Layout ระดับโครงสร้างหลัก เช่น Navigation Bar, Sidebar สลับเป็น Drawer, Hero Banner

### ควรใช้ Container Queries (`@container`, `@sm:`, `@md:`)
- การสร้าง **Reusable Design System Components** เช่น Product Card, Comment Box, Video Player Card ที่ต้องสามารถนำไปวางในช่อง Sidebar แคบ หรือช่อง Content กว้าง ได้โดยหน้าตาปรับเปลี่ยนอัตโนมัติ

## 7. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: ปรัชญา "Mobile-First" ใน Tailwind CSS มีผลต่อการเขียน CSS อย่างไร และข้อดีคืออะไร?
**แนวทางคำตอบ**: 
Mobile-first หมายถึงการเขียนสไตล์พื้นฐาน (คลาสที่ไม่มี prefix) เพื่อตอบโจทย์หน้าจอสมาร์ตโฟนที่มีพื้นที่จำกัดที่สุดก่อน จากนั้นจึงใช้ Utility Prefixes เช่น `sm:`, `md:`, `lg:` ซึ่งคอมไพล์เป็น `@media (min-width: ...)` เพื่อขยายหรือเพิ่มเติมเลย์เอาต์เมื่อหน้าจอกว้างขึ้น ข้อดีคือลดความซับซ้อนของการเขียนโค้ด CSS ลบล้าง (Overriding) ช่วยให้หน้าเว็บบนมือถือโหลดได้เบาและรวดเร็วที่สุด และป้องกันอาการเลย์เอาต์เพี้ยนเมื่อเปิดบนอุปกรณ์หน้าจอแปลกใหม่

### Q2: ความแตกต่างที่สำคัญระหว่าง Media Queries ปกติ (`md:`) กับ Container Queries (`@md:`) ใน Tailwind v4 คืออะไร?
**แนวทางคำตอบ**: 
`md:` ประเมินจาก **Viewport (ขนาดหน้าต่างบราวเซอร์ทั้งหมด)** ในขณะที่ `@md:` ประเมินจาก **ขนาดความกว้างของ Parent Element ที่ระบุ `@container`** ข้อได้เปรียบของ Container Queries คือช่วยให้คอมโพเนนต์มีสถาปัตยกรรมแบบแยกตัวอิสระ (Encapsulated) อย่างแท้จริง โดยคอมโพเนนต์จะปรับสไตล์ตามพื้นที่ที่มันได้รับจริง ไม่ว่าหน้าต่างบราวเซอร์จะใหญ่ระดับเดสก์ท็อป แต่ถ้าคอมโพเนนต์ถูกวางในช่องแคบ 300px มันจะแสดงผลในโหมดกะทัดรัดอย่างถูกต้อง
