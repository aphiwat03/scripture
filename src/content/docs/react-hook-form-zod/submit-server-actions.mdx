## 1. แนวคิด (Concept)

ในยุคของ **Next.js 16** และ **React 19** รูปแบบการส่งข้อมูลจากแบบฟอร์ม (Form Submission) ถูกยกระดับให้มีความปลอดภัย ยืดหยุ่น และมีประสิทธิภาพสูงสุด โดยมี 2 กระบวนทัศน์หลักที่วิศวกรซอฟต์แวร์เลือกใช้:

1. **Client Mutation Paradigm (TanStack Query `useMutation`)**: เหมาะสำหรับสถาปัตยกรรมที่แยก Front-end และ Back-end (เช่น Next.js คุยกับ NestJS หรือ Go Microservices ผ่าน REST/GraphQL) โดยเน้นการบริหารจัดการ Cache, การทำ Optimistic Updates และ Invalidation ทั่วทั้งระบบ
2. **Server Actions Paradigm (`'use server'`)**: ฟีเจอร์หลักของ Next.js App Router ที่อนุญาตให้เรียกฟังก์ชัน Asynchronous บนเซิร์ฟเวอร์ได้โดยตรงจากคอมโพเนนต์ ลดภาระการเขียน API Route และ Type Definition ซ้ำซ้อน

หัวใจสำคัญของการผสานสถาปัตยกรรมนี้คือ **Single Source of Truth**: เราใช้ **Zod Schema ไฟล์เดียวกัน** เพื่อตรวจสอบความถูกต้องทั้งบน Client-side (Instant Feedback ผ่าน RHF `zodResolver`) และบน Server Action / API (Security Enforcement) พร้อมทั้งแปลงข้อผิดพลาดจากฝั่งเซิร์ฟเวอร์ (เช่น Business logic errors, Duplicate key) กลับมาแสดงตรงช่องอินพุตด้วย **`form.setError()`** อย่างไร้รอยต่อ

## 2. หลักการเบื้องหลัง (Under the Hood)

### 2.1 วงจรชีวิตการส่งข้อมูลและการไหลของข้อผิดพลาด (Submission Flow)

```
[ ผู้ใช้กด Submit ]
       │
       ▼
[ RHF handleSubmit ]
       │
       ├─► [ Client-side Zod Validation (zodResolver) ]
       │     └─► ❌ หากไม่ผ่าน: แสดงข้อผิดพลาดทันที (Zero Network Request)
       │
       ▼ ✅ ผ่านการตรวจสอบฝั่งไคลเอนต์
[ ปิดการกดปุ่มซ้ำ (isSubmitting = true) ]
       │
       ▼
[ ส่งข้อมูลไปยัง Server Action หรือ API Mutation ]
       │
       ├─► [ Server-side Zod Parsing (schema.safeParse) ]
       │     └─► ❌ หากข้อมูลถูกดัดแปลง: ปฏิเสธคำขอทันที
       │
       ├─► [ Business Logic Execution (DB Insert, Payment, etc.) ]
       │     └─► ❌ เกิดความผิดพลาดทางธุรกิจ (เช่น "Email นี้มีผู้ใช้งานแล้ว")
       │           ส่ง Structured Error Response กลับมา
       │
       ▼ ✅ สำเร็จ
[ Invalidate Cache + แสดง Toast Notification + รีเซ็ตฟอร์ม ]
```

### 2.2 โครงสร้างผลลัพธ์ของ Server Action (Action State Pattern)

เพื่อให้สามารถส่ง Error กลับมายังหน้าบ้านได้อย่างเป็นระบบ Server Action ไม่ควรโยน Unhandled Exception (`throw new Error()`) ซึ่งจะทำให้ Next.js พ่น Internal Server Error 500 แต่ควรคืนค่าเป็น **Result Object** ที่มีโครงสร้างชัดเจน:

```typescript
export type ActionResult<T> =
  | { success: true; data: T }
  | {
      success: false;
      error: string; // ข้อความภาพรวม (Root error)
      fieldErrors?: Record<string, string[]>; // ข้อความเจาะจงรายฟิลด์
    };
```

### 2.3 การเชื่อมโยง Error เข้ากับ RHF ด้วย `form.setError()`

เมื่อไคลเอนต์ได้รับ `fieldErrors` จากเซิร์ฟเวอร์ เราสามารถวนลูปแมปข้อความกลับเข้าไปยังฟิลด์ของ RHF ได้โดยตรง:

```typescript
if (!result.success && result.fieldErrors) {
  Object.entries(result.fieldErrors).forEach(([fieldName, messages]) => {
    form.setError(fieldName as any, {
      type: 'server',
      message: messages[0],
    });
  });
}
```

### 2.4 กลไกป้องกัน Double Submission

การกดปุ่ม Submit ซ้ำๆ ขณะระบบกำลังประมวลผลเครือข่าย อาจก่อให้เกิดปัญหาบันทึกข้อมูลซ้ำซ้อน (Duplicate Database Records) หรือการตัดเงินซ้ำ เราป้องกันได้ 3 ชั้น:
1. **RHF `formState.isSubmitting`**: จะกลายเป็น `true` ทันทีที่ `handleSubmit` เริ่มประมวลผล async function
2. **UI Disabled State**: ปิดการคลิกปุ่ม `<button disabled={isSubmitting}>` และเปลี่ยนเคอร์เซอร์
3. **Pending Spinner**: แสดงตัวหมุนโหลดเพื่อสื่อสารให้ผู้ใช้ทราบว่าระบบกำลังทำงาน

## 3. ตัวอย่างโค้ด (TypeScript / TSX)

ตัวอย่างระบบสร้างองค์กรใหม่ (Create Enterprise Organization Form) ที่สาธิตทั้ง **Single Source of Truth Zod Schema**, **Next.js 16 Server Action**, และ **TanStack Query Mutation**:

### 1. Shared Schema (`src/features/organizations/schemas/org.schema.ts`)

```typescript filename="src/features/organizations/schemas/org.schema.ts"
import { z } from 'zod';

export const createOrganizationSchema = z.object({
  organizationName: z
    .string()
    .min(3, 'ชื่อองค์กรต้องมีความยาวอย่างน้อย 3 ตัวอักษร')
    .max(50, 'ชื่อองค์กรต้องไม่เกิน 50 ตัวอักษร'),
  slug: z
    .string()
    .min(3, 'Slug ต้องมีอย่างน้อย 3 ตัวอักษร')
    .regex(/^[a-z0-9-]+$/, 'Slug ต้องเป็นตัวพิมพ์เล็ก ตัวเลข หรือขีดกลาง (-) เท่านั้น'),
  billingEmail: z.string().email('กรุณาระบุอีเมลสำหรับรับใบแจ้งหนี้ให้ถูกต้อง'),
  subscriptionTier: z.enum(['STARTER', 'PROFESSIONAL', 'ENTERPRISE']),
  seatsCount: z.number().int().min(5, 'จำนวนผู้ใช้งานขั้นต่ำคือ 5 บัญชี'),
});

export type CreateOrganizationInput = z.infer<typeof createOrganizationSchema>;
```

### 2. Next.js 16 Server Action (`src/features/organizations/actions/org.actions.ts`)

```typescript filename="src/features/organizations/actions/org.actions.ts"
'use server';

import { createOrganizationSchema, type CreateOrganizationInput } from '../schemas/org.schema';

export type ActionResponse = {
  success: boolean;
  message?: string;
  fieldErrors?: Record<string, string[]>;
  data?: { id: string; name: string };
};

export async function createOrganizationAction(
  rawInput: CreateOrganizationInput
): Promise<ActionResponse> {
  // 1. ตรวจสอบความปลอดภัยฝั่งเซิร์ฟเวอร์ซ้ำอีกครั้ง (Never Trust the Client)
  const parseResult = createOrganizationSchema.safeParse(rawInput);
  if (!parseResult.success) {
    return {
      success: false,
      message: 'ข้อมูลไม่ผ่านการตรวจสอบความปลอดภัย',
      fieldErrors: parseResult.error.flatten().fieldErrors,
    };
  }

  const { slug, billingEmail, organizationName, subscriptionTier, seatsCount } = parseResult.data;

  try {
    // 2. จำลองการตรวจสอบ Business Logic (เช่น Slug ชนในฐานข้อมูล)
    if (slug === 'google' || slug === 'apple' || slug === 'microsoft') {
      return {
        success: false,
        fieldErrors: {
          slug: ['ชื่อ Slug นี้เป็นชื่อสงวนหรือถูกใช้งานไปแล้วในระบบ'],
        },
      };
    }

    // 3. จำลองการบันทึกข้อมูลลงฐานข้อมูล (Prisma / Drizzle)
    await new Promise((resolve) => setTimeout(resolve, 1000));

    return {
      success: true,
      data: {
        id: `org_${Date.now()}`,
        name: organizationName,
      },
    };
  } catch (error) {
    return {
      success: false,
      message: 'เกิดข้อผิดพลาดในการเชื่อมต่อฐานข้อมูล กรุณาลองใหม่อีกครั้ง',
    };
  }
}
```

### 3. Form Component (`src/features/organizations/components/CreateOrganizationForm.tsx`)

```tsx filename="src/features/organizations/components/CreateOrganizationForm.tsx"
'use client';

import React from 'react';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { toast } from 'sonner'; // Sonner Toast Library
import { Building2, Loader2, Sparkles } from 'lucide-react';

import {
  createOrganizationSchema,
  type CreateOrganizationInput,
} from '../schemas/org.schema';
import { createOrganizationAction } from '../actions/org.actions';

export function CreateOrganizationForm() {
  const {
    register,
    handleSubmit,
    setError,
    reset,
    formState: { errors, isSubmitting },
  } = useForm<CreateOrganizationInput>({
    resolver: zodResolver(createOrganizationSchema),
    defaultValues: {
      organizationName: '',
      slug: '',
      billingEmail: '',
      subscriptionTier: 'PROFESSIONAL',
      seatsCount: 10,
    },
    mode: 'onTouched',
  });

  const onSubmit = async (values: CreateOrganizationInput) => {
    try {
      // เรียกใช้ Next.js 16 Server Action
      const response = await createOrganizationAction(values);

      if (!response.success) {
        // หากเซิร์ฟเวอร์ส่ง Field Errors กลับมา ให้ map เข้า RHF โดยตรง
        if (response.fieldErrors) {
          Object.entries(response.fieldErrors).forEach(([field, messages]) => {
            setError(field as keyof CreateOrganizationInput, {
              type: 'server',
              message: messages[0],
            });
          });
        }

        if (response.message) {
          toast.error(response.message);
        }
        return;
      }

      // ส่งข้อมูลสำเร็จ
      toast.success(`สร้างองค์กร "${response.data?.name}" เรียบร้อยแล้ว!`);
      reset();
    } catch (err) {
      toast.error('ไม่สามารถส่งคำขอได้ กรุณาตรวจสอบสัญญาณอินเทอร์เน็ต');
    }
  };

  return (
    <div className="max-w-xl mx-auto p-8 bg-white dark:bg-slate-900 border border-slate-200 dark:border-slate-800 rounded-2xl shadow-xl space-y-6">
      <div className="flex items-center space-x-3">
        <div className="p-2.5 bg-blue-50 dark:bg-blue-950 text-blue-600 rounded-xl">
          <Building2 className="w-6 h-6" />
        </div>
        <div>
          <h2 className="text-xl font-bold text-slate-900 dark:text-white">สร้างพื้นที่ทำงานองค์กรใหม่</h2>
          <p className="text-xs text-slate-500">กำหนดชื่อโดเมนและแพ็กเกจการใช้งานสำหรับทีมของคุณ</p>
        </div>
      </div>

      <form onSubmit={handleSubmit(onSubmit)} className="space-y-4">
        {/* Organization Name */}
        <div>
          <label className="text-xs font-semibold text-slate-700 dark:text-slate-300">ชื่อองค์กร (Company Name)</label>
          <input
            {...register('organizationName')}
            placeholder="Acme Corporation Ltd."
            disabled={isSubmitting}
            className="w-full mt-1 px-3 py-2 text-sm border rounded-md dark:bg-slate-800"
          />
          {errors.organizationName && (
            <p className="text-xs text-red-500 mt-1">{errors.organizationName.message}</p>
          )}
        </div>

        {/* Slug */}
        <div>
          <label className="text-xs font-semibold text-slate-700 dark:text-slate-300">Workspace URL Slug</label>
          <div className="flex mt-1">
            <span className="inline-flex items-center px-3 text-xs bg-slate-100 dark:bg-slate-800 border border-r-0 rounded-l-md text-slate-500">
              app.cloud.io/
            </span>
            <input
              {...register('slug')}
              placeholder="acme-corp"
              disabled={isSubmitting}
              className="w-full px-3 py-2 text-sm border rounded-r-md dark:bg-slate-800 font-mono"
            />
          </div>
          {errors.slug && <p className="text-xs text-red-500 mt-1">{errors.slug.message}</p>}
        </div>

        {/* Billing Email */}
        <div>
          <label className="text-xs font-semibold text-slate-700 dark:text-slate-300">อีเมลแผนกบัญชี (Billing Email)</label>
          <input
            type="email"
            {...register('billingEmail')}
            placeholder="finance@acme-corp.com"
            disabled={isSubmitting}
            className="w-full mt-1 px-3 py-2 text-sm border rounded-md dark:bg-slate-800"
          />
          {errors.billingEmail && (
            <p className="text-xs text-red-500 mt-1">{errors.billingEmail.message}</p>
          )}
        </div>

        {/* Subscription Tier & Seats */}
        <div className="grid grid-cols-2 gap-4">
          <div>
            <label className="text-xs font-semibold text-slate-700 dark:text-slate-300">แพ็กเกจ (Subscription)</label>
            <select
              {...register('subscriptionTier')}
              disabled={isSubmitting}
              className="w-full mt-1 px-3 py-2 text-sm border rounded-md dark:bg-slate-800"
            >
              <option value="STARTER">Starter Tier</option>
              <option value="PROFESSIONAL">Professional Tier</option>
              <option value="ENTERPRISE">Enterprise Tier</option>
            </select>
          </div>

          <div>
            <label className="text-xs font-semibold text-slate-700 dark:text-slate-300">จำนวนที่นั่งผู้ใช้ (Seats)</label>
            <input
              type="number"
              {...register('seatsCount', { valueAsNumber: true })}
              disabled={isSubmitting}
              className="w-full mt-1 px-3 py-2 text-sm border rounded-md dark:bg-slate-800"
            />
            {errors.seatsCount && (
              <p className="text-xs text-red-500 mt-1">{errors.seatsCount.message}</p>
            )}
          </div>
        </div>

        {/* Submit Button พร้อมระบบป้องกัน Double Click */}
        <button
          type="submit"
          disabled={isSubmitting}
          className="w-full mt-4 flex items-center justify-center space-x-2 py-2.5 px-4 rounded-lg bg-blue-600 hover:bg-blue-700 text-white font-medium text-sm transition-all shadow-md disabled:opacity-50 disabled:cursor-not-allowed"
        >
          {isSubmitting ? (
            <>
              <Loader2 className="w-4 h-4 animate-spin" />
              <span>กำลังสร้างองค์กรในระบบ...</span>
            </>
          ) : (
            <>
              <Sparkles className="w-4 h-4" />
              <span>เริ่มต้นใช้งานพื้นที่ทำงาน</span>
            </>
          )}
        </button>
      </form>
    </div>
  );
}
```

## 4. เทียบกับวิธีเดิม

| มิติการเปรียบเทียบ | วิธีเดิม: สร้าง Express/Next API Route แยก | วิธีโมเดิร์น: Next.js 16 Server Actions + Shared Zod |
| :--- | :--- | :--- |
| **การจัดการ Schema** | ต้องเขียน DTO บน Backend และเขียน Zod แยกบน Frontend เสี่ยงหลุดสเปก | ใช้ **Single Zod Schema** อันเดียวกัน นำเข้าได้ทั้งหน้าบ้านและหลังบ้าน |
| **การส่ง Error กลับหน้าจอ** | Backend ส่ง HTTP 400 ต้องเขียนโค้ด Parse JSON และจับคู่สตริงเอง | เซิร์ฟเวอร์ส่ง `fieldErrors` คืนมา แล้ววนลูปสั่ง `form.setError()` ในบรรทัดเดียว |
| **Network Overhead** | ต้องเปิด Endpoint ใหม่ จัดการ CORS, Headers, และ Cookie Serialization | Server Action จัดการ RPC Communication และ Cookie Session ให้โดยอัตโนมัติ |
| **Type Safety** | เสี่ยง Types Desynchronization ระหว่าง Client DTO กับ Server DTO | Full End-to-End Type Safety แบบ 100% |

## 5. ผิด vs ถูก (Anti-patterns vs Best Practices)

### 5.1 ผิด ❌: ไว้วางใจ Client Validation แล้วไม่ Validate ซ้ำบน Server Action

```typescript
// ❌ ผิดมหันต์ (Security Vulnerability): เชื่อว่าข้อมูลถูกต้องเพราะผ่าน RHF แล้ว
export async function badAction(data: CreateOrganizationInput) {
  'use server';
  // แฮกเกอร์สามารถยิงคำขอผ่าน cURL ข้ามหน้าเว็บเข้ามาสร้างข้อมูลที่ผิดกฎหมายได้ทันที!
  await db.organization.create({ data });
}
```

```typescript
// ✅ ถูกต้อง: เรียก safeParse บนเซิร์ฟเวอร์เสมอ
export async function goodAction(data: CreateOrganizationInput) {
  'use server';
  const validated = createOrganizationSchema.safeParse(data);
  if (!validated.success) {
    return { success: false, errors: validated.error.flatten().fieldErrors };
  }
  await db.organization.create({ data: validated.data });
}
```

### 5.2 ผิด ❌: ละเลยการ Disabled ปุ่ม Submit ทำให้เกิด Double Submission

```tsx
// ❌ ผิด: ผู้ใช้ที่เน็ตช้าจะกดย้ำๆ จนสร้างข้อมูลซ้ำในฐานข้อมูล
<button type="submit">
  บันทึกข้อมูล
</button>
```

```tsx
// ✅ ถูกต้อง: ปิดปุ่มและแสดงสถานะ Loading ด้วย isSubmitting
<button type="submit" disabled={isSubmitting}>
  {isSubmitting ? <Spinner /> : 'บันทึกข้อมูล'}
</button>
```

## 6. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้ Next.js Server Actions เมื่อ:
- พัฒนาเว็บแอปพลิเคชันแบบ Full-stack บน Next.js 16 App Router
- มีการติดต่อ Database (Prisma, Drizzle) หรือ Internal Microservices โดยตรง
- ต้องการลด Boilerplate ในการสร้าง REST API Endpoint สำหรับการ Submit ฟอร์มภายใน

### ควรใช้ TanStack Query `useMutation` เมื่อ:
- Frontend ต้องติดต่อกับ External Backend แยกต่างหาก (เช่น Java Spring Boot, NestJS, Go)
- ต้องการทำ **Optimistic Updates** ที่ซับซ้อน หรือมี Query Caches หลายชุดในหน้าเว็บที่ต้อง Invalidate พร้อมกันอย่างเป็นระบบ

## 7. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: ในเมื่อเราใช้ Zod Resolver ตรวจสอบความถูกต้องบน Client-side ก่อนส่งแล้ว ทำไมเรายังจำเป็นต้องรัน `safeParse` ใน Server Action อีกครั้ง?
**แนวทางตอบแบบ Senior**:
"นี่คือหลักการพื้นฐานที่สุดของความปลอดภัยทางไซเบอร์ที่เรียกว่า **'Never Trust the Client'** ครับ
1. การตรวจสอบบน Client-side (ผ่าน React Hook Form + Zod) มีวัตถุประสงค์เพื่อ **User Experience (UX)** เท่านั้น เพื่อแจ้งเตือนผู้ใช้งานแบบ Real-time โดยไม่ต้องเสียเวลาส่ง Network Request
2. อย่างไรก็ตาม โค้ดฝั่ง Client-side สามารถถูกบายพาส (Bypass) ได้อย่างง่ายดายโดยผู้ไม่ประสงค์ดี เช่น การใช้ cURL, Postman, การแก้ไข JavaScript บน Browser Console หรือการดัดแปลง Payload ผ่าน Proxy
3. ดังนั้น การเรียก `safeParse()` บน Server Action หรือ API Endpoint คือ **Security Boundary แท้จริง** ที่คอยคัดกรองข้อมูลก่อนลงฐานข้อมูล เพื่อป้องกัน Injection Attacks, การใส่ข้อมูลผิดประเภท, และการละเมิด Integrity ของระบบครับ"

### Q2: หากเกิดข้อผิดพลาดทางธุรกิจบนฝั่งเซิร์ฟเวอร์ (เช่น Duplicate Email) เราควรส่ง Error กลับมายัง React Hook Form อย่างไรให้สะอาดและ Type-safe ที่สุด?
**แนวทางตอบแบบ Senior**:
"เราไม่ควรโยน Raw Error ข้ามแดน แต่ควรใช้ **Result Object Pattern** ครับ:
1. ฝั่ง Server Action ให้ส่ง Response กลับมาเป็น Object เช่น `{ success: false, fieldErrors: { email: ['อีเมลนี้ถูกใช้งานแล้ว'] } }`
2. ฝั่ง Client Component ภายในฟังก์ชัน `onSubmit` เมื่อตรวจสอบพบว่า `!response.success`:
   - ให้นำ `fieldErrors` มาวนลูปเรียกใช้ **`form.setError('email', { type: 'server', message: response.fieldErrors.email[0] })`**
3. ผลลัพธ์คือ RHF จะนำข้อความนี้ไปผูกเข้ากับ `fieldState.error` ของช่อง Input นั้นโดยอัตโนมัติ ทำให้กรอบอินพุตกลายเป็นสีแดงและแสดงข้อความแจ้งเตือนทันที เหมือนกับข้อผิดพลาดที่เกิดจาก Client Validation ทุกประการครับ"
