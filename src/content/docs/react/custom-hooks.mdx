## 1. แนวคิด (Concept)

**Custom Hooks** คือฟังก์ชัน JavaScript/TypeScript ธรรมดาที่ขึ้นต้นด้วยคำว่า `use` (เช่น `useDebounce`, `useLocalStorage`) ซึ่งมีคุณสมบัติพิเศษคือสามารถเรียกใช้งาน React Hooks ตัวอื่นๆ ข้างในได้

แนวคิดนี้สร้างขึ้นเพื่อสกัดตรรกะการทำงาน (Logic) ที่ซ้ำซ้อนกันในหลายๆ คอมโพเนนต์ให้ออกมาเป็นก้อนที่นำกลับมาใช้ซ้ำได้ โดยไม่ต้องทำซ้ำโค้ด UI (Separation of Concerns: แยก Logic ออกจาก View)

---

## 2. กฎเหล็กของ Custom Hooks (Rules of Hooks)

1. **ต้องขึ้นต้นด้วย `use` เสมอ**: เพื่อให้ React Linter ทราบว่านี่คือ Hook และทำการตรวจสอบกฎความปลอดภัยให้
2. **เรียกใช้เฉพาะที่ Top Level**: ห้ามเรียกใช้ Hook ภายในเงื่อนไข `if`, ลูป `for`, หรือฟังก์ชันย่อยซ้อนใน
3. **Custom Hooks แชร์เฉพาะ Logic ไม่แชร์ State**: หากคอมโพเนนต์ A และคอมโพเนนต์ B เรียกใช้ `useDebounce()` เหมือนกัน ทั้งคู่จะมี State ภายในแยกขาดจากกันคนละก้อนอย่างสิ้นเชิง

## 3. ตัวอย่างโค้ด (TypeScript)

### ตัวอย่างที่ 1: `useDebounce` ชะลอการยิงคำค้นหา

```typescript filename="hooks/useDebounce.ts"
import { useState, useEffect } from 'react';

export function useDebounce<T>(value: T, delay: number = 500): T {
  const [debouncedValue, setDebouncedValue] = useState<T>(value);

  useEffect(() => {
    // ตั้งเวลาหน่วงการอัปเดตค่า
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    // หาก value เปลี่ยนก่อนครบกำหนด ให้ยกเลิก timer เดิม
    return () => {
      clearTimeout(timer);
    };
  }, [value, delay]);

  return debouncedValue;
}
```

### ตัวอย่างที่ 2: `useLocalStorage` ซิงค์ State ลง Browser Storage อย่างปลอดภัย

```typescript filename="hooks/useLocalStorage.ts"
'use client';

import { useState, useEffect } from 'react';

export function useLocalStorage<T>(key: string, initialValue: T): [T, (val: T) => void] {
  // อ่านค่าเริ่มต้นจาก localStorage หรือ fallback ไป initialValue
  const [storedValue, setStoredValue] = useState<T>(() => {
    if (typeof window === 'undefined') return initialValue;
    try {
      const item = window.localStorage.getItem(key);
      return item ? (JSON.parse(item) as T) : initialValue;
    } catch {
      return initialValue;
    }
  });

  const setValue = (value: T) => {
    try {
      setStoredValue(value);
      if (typeof window !== 'undefined') {
        window.localStorage.setItem(key, JSON.stringify(value));
      }
    } catch (error) {
      console.error(error);
    }
  };

  return [storedValue, setValue];
}
```

## 4. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

- *ควรใช้*:
  - เมื่อมีตรรกะซ้ำซ้อนในหลายคอมโพเนนต์ เช่น การดัก Event การเลื่อนจอ (Scroll), การตรวจสถานะอินเทอร์เน็ต (Online/Offline)
  - เพื่อลดความยาวของโค้ดในคอมโพเนนต์ UI ให้สะอาดและอ่านเข้าใจง่าย
- *ไม่ควรใช้*: กับฟังก์ชันยูทิลิตี้ธรรมดาที่ไม่มีการเรียกใช้ React Hooks (ถ้าฟังก์ชันไม่มี `useState` หรือ `useEffect` ให้เขียนเป็น helper function ธรรมดา ไม่ต้องขึ้นต้นด้วย `use`)

## 5. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: คอมโพเนนต์สองตัวที่เรียกใช้ Custom Hook ตัวเดียวกัน จะแชร์ State ร่วมกันหรือไม่?
**แนวทางคำตอบ**: **ไม่แชร์ร่วมกัน** Custom Hook ทำหน้าที่แชร์เฉพาะตรรกะหรือกระบวนการทำงาน (Stateful Logic) เท่านั้น แต่ตัวแปร State และ Effect ที่ถูกสร้างขึ้นภายในจะผูกติดกับแต่ละอินสแตนซ์ของคอมโพเนนต์แยกขาดจากกัน หากต้องการแชร์ State จริงๆ ต้องใช้ Context หรือ Global State Manager เช่น Zustand
