# Git Version Control

(ระบบควบคุมเวอร์ชันมาตรฐานระดับโลกที่จำเป็นสำหรับนักพัฒนาทุกคน ครอบคลุมตั้งแต่คำสั่งพื้นฐาน, โครงสร้างข้อความ Commit แบบ Conventional Commits, กลยุทธ์การแตก Branch, เทคนิค Merge vs Rebase, การกู้คืนโค้ด, และการทำงานร่วมกันเป็นทีม)

<Callout type="tip" title="ทำไม Git จึงเป็นทักษะที่ขาดไม่ได้ของ Fullstack Developer">
Git คือระบบ Distributed Version Control System (DVCS) ที่บันทึกประวัติการเปลี่ยนแปลงของไฟล์ในรูปแบบ Snapshot ที่มี Hash ปลอดภัย (SHA-1/SHA-256) การเข้าใจ Git อย่างลึกซึ้งไม่เพียงช่วยให้คุณไม่ทำโค้ดในทีมสูญหาย แต่ยังเป็นหัวใจสำคัญในการวางระบบ **CI/CD Automation**, การทำ **Code Review**, และการสร้าง **Semantic Versioning** อัตโนมัติ
</Callout>

## สรุปย่อคำนำหน้า Commit ยอดนิยม (Quick Reference)

```text
<type>(<scope>): <description>

[ตัวอย่าง]
feat(cart): add wagyu beef weight calculation in checkout
fix(payment): resolve decimal rounding error in promptpay webhook
chore(deps): update next from 16.4.1 to 16.4.2
```

- **`feat`**: ฟีเจอร์ใหม่สำหรับผู้ใช้ (Minor version bump)
- **`fix`**: แก้ไขข้อผิดพลาดหรือบั๊กในระบบ (Patch version bump)
- **`chore`**: งานบำรุงรักษาทั่วไป ไม่กระทบโค้ดระบบและไม่ใช่เทสต์
- **`docs`**: อัปเดตเอกสารคู่มือหรือ README
- **`style`**: จัดรูปแบบโค้ด เว้นวรรค เซมิโคลอน (ไม่มีผลต่อการทำงาน)
- **`refactor`**: ปรับโครงสร้างโค้ดภายในโดยไม่เพิ่มฟีเจอร์และไม่แก้บั๊ก
- **`perf`**: ปรับปรุงประสิทธิภาพความเร็วหรือลดการใช้ Memory
- **`test`**: เพิ่มหรือแก้ไขชุดทดสอบ Unit/Integration/E2E
- **`build`**: แก้ไขระบบบิลด์, dependencies, หรือ npm scripts
- **`ci`**: ปรับแต่งคอนฟิกของ CI/CD เช่น GitHub Actions
- **`revert`**: ยกเลิก Commit ก่อนหน้า
