## 1. แนวคิด (Concept)

`useQuery` คือ Hook หัวใจหลักของ **TanStack Query v5** ที่ใช้สำหรับการ "อ่านข้อมูล" (Read-only Data Fetching) จากฝั่งเซิร์ฟเวอร์มาแสดงผลบนคอมโพเนนต์

ในเวอร์ชัน 5 มีการปรับปรุงโครงสร้างที่สำคัญ:
1. **Object Syntax เพียงรูปแบบเดียว**: บังคับให้ส่ง Parameter เป็น Object ตัวเดียว `{ queryKey, queryFn, ...options }` เสมอ เพื่อลดความสับสนและเพิ่มความแม่นยำของ TypeScript
2. **การปรับเปลี่ยนคำว่า Loading**: แนะนำให้ใช้ **`isPending`** แทน `isLoading` เดิม เพื่อแยกความแตกต่างระหว่าง "ยังไม่มีข้อมูลในแคชเลย" กับ "กำลังดึงข้อมูลอยู่ผ่านเครือข่าย"

สถานะผลลัพธ์ที่สำคัญประกอบด้วย:
- **`data`**: ข้อมูลที่ดึงสำเร็จ (Type-safe ตามที่คืนค่าจาก `queryFn`)
- **`isPending`**: เป็น `true` เมื่อยัง **ไม่มีข้อมูลในแคช** และยังดึงไม่เสร็จ (ใช้สำหรับแสดง Skeleton หรือ Full Loading Spinner)
- **`isFetching`**: เป็น `true` ทุกครั้งที่ **มีคำขอกำลังวิ่งอยู่บน Network** (รวมทั้งการดึงครั้งแรก และการดึงอัปเดตเบื้องหลัง)
- **`isError`** และ **`error`**: สถานะเมื่อ `queryFn` ขว้าง (throw) Error ออกมา
- **`refetch`**: ฟังก์ชันสั่งดึงข้อมูลใหม่ทันทีด้วยตนเอง (Manual Trigger)

## 2. หลักการเบื้องหลัง (Under the Hood)

### โมเดล State Machine 2 มิติ: `status` vs `fetchStatus`

TanStack Query v5 แยกสถานะการทำงานออกเป็น 2 มิติที่เป็นอิสระต่อกัน (Orthogonal States):

```
+--------------------------------------------------------------------------+
| status (สถานะข้อมูลในแคช)                                                   |
| - 'pending' : ยังไม่มีข้อมูลในแคช                                           |
| - 'error'   : มีข้อผิดพลาดเกิดขึ้น                                          |
| - 'success' : มีข้อมูลพร้อมใช้งานแล้ว                                         |
+--------------------------------------------------------------------------+
                                     x
+--------------------------------------------------------------------------+
| fetchStatus (สถานะกิจกรรม Network)                                        |
| - 'fetching': กำลังยิง Request อยู่บนเครือข่าย                               |
| - 'paused'  : พักการยิงไว้ชั่วคราว (เช่น เน็ตหลุด หรือรอ offline retry)     |
| - 'idle'    : ไม่ได้ทำกิจกรรมทาง Network ใดๆ อยู่นิ่งๆ                      |
+--------------------------------------------------------------------------+
```

### การคำนวณ Flag ต่างๆ ใน v5:
- `isPending = status === 'pending'` (ไม่มีข้อมูลในมือ)
- `isFetching = fetchStatus === 'fetching'` (เครือข่ายกำลังทำงาน)
- `isLoading = isPending && isFetching` (การดึงข้อมูลครั้งแรกสุดที่ยังไม่มีแคช)

โมเดล 2 มิตินี้ช่วยแก้ปัญหาคลาสสิก: ในกรณีที่ผู้ใช้เปิดหน้าเว็บขณะออฟไลน์ `status` อาจเป็น `'pending'` แต่ `fetchStatus` เป็น `'paused'` แทนที่จะเป็น `'fetching'` ทำให้เราแสดง UI "กำลังรอเชื่อมต่อเน็ต" ได้อย่างถูกต้อง

## 3. ตัวอย่างโค้ด (TypeScript / TSX)

หน้าแสดงรายละเอียดสินค้าและสต็อก (`ProductDetails.tsx`):

```tsx filename="src/features/products/components/ProductDetails.tsx"
'use client';

import React from 'react';
import { useQuery } from '@tanstack/react-query';

interface Product {
  id: string;
  sku: string;
  name: string;
  description: string;
  price: number;
  stockQuantity: number;
  category: string;
  rating: number;
}

interface ProductDetailsProps {
  productId: string;
}

// ฟังก์ชัน API Client ที่มี Type ปลอดภัย
async function fetchProductById(id: string): Promise<Product> {
  const res = await fetch(`/api/products/${id}`);
  if (!res.ok) {
    if (res.status === 404) {
      throw new Error('ไม่พบสินค้ารหัสนี้ในระบบ');
    }
    throw new Error('เกิดข้อผิดพลาดในการโหลดข้อมูลสินค้า');
  }
  return res.json();
}

export function ProductDetails({ productId }: ProductDetailsProps) {
  const {
    data: product,
    isPending,
    isError,
    error,
    isFetching,
    refetch,
  } = useQuery<Product>({
    queryKey: ['products', 'detail', productId],
    queryFn: () => fetchProductById(productId),
    staleTime: 30 * 1000, // ข้อมูลถือว่าสดใหม่ 30 วินาที
  });

  // 1. กำลังโหลดครั้งแรกสุด (ยังไม่มีแคช): แสดง Skeleton
  if (isPending) {
    return (
      <div className="space-y-4 p-6 border rounded-xl animate-pulse">
        <div className="h-8 bg-gray-200 rounded w-2/3" />
        <div className="h-4 bg-gray-200 rounded w-1/4" />
        <div className="h-20 bg-gray-200 rounded w-full" />
        <div className="h-10 bg-gray-200 rounded w-1/3" />
      </div>
    );
  }

  // 2. เกิด Error: แสดงปุ่มกดยิงใหม่
  if (isError) {
    return (
      <div className="rounded-xl border border-red-200 bg-red-50 p-6 text-center">
        <p className="font-semibold text-red-600 mb-2">ไม่สามารถโหลดข้อมูลสินค้าได้</p>
        <p className="text-sm text-red-500 mb-4">{error.message}</p>
        <button
          onClick={() => refetch()}
          className="rounded-lg bg-red-600 px-4 py-2 text-sm font-medium text-white hover:bg-red-700"
        >
          ลองใหม่อีกครั้ง
        </button>
      </div>
    );
  }

  // 3. มีข้อมูลแสดงผล และมี indicator แจ้งเตือนเมื่อกำลังซิงค์เบื้องหลัง
  return (
    <div className="relative rounded-xl border border-gray-200 bg-white p-6 shadow-sm">
      {/* Background Fetching Badge */}
      {isFetching && (
        <div className="absolute top-4 right-4 flex items-center gap-1 rounded-full bg-blue-50 px-2.5 py-1 text-xs text-blue-600">
          <span className="h-2 w-2 rounded-full bg-blue-500 animate-ping" />
          <span>กำลังอัปเดตข้อมูล...</span>
        </div>
      )}

      <div className="text-xs font-semibold uppercase tracking-wider text-blue-600">
        หมวดหมู่: {product.category}
      </div>
      <h1 className="mt-1 text-2xl font-bold text-gray-900">{product.name}</h1>
      <p className="text-sm text-gray-400">SKU: {product.sku}</p>

      <p className="mt-4 text-gray-600 leading-relaxed">{product.description}</p>

      <div className="mt-6 flex items-center justify-between border-t pt-4">
        <div>
          <span className="text-sm text-gray-500">ราคาขาย</span>
          <p className="text-3xl font-extrabold text-emerald-600">
            ฿{product.price.toLocaleString()}
          </p>
        </div>

        <div className="text-right">
          <span className="text-sm text-gray-500">คงเหลือในสต็อก</span>
          <p className={`font-semibold ${product.stockQuantity > 0 ? 'text-gray-900' : 'text-red-500'}`}>
            {product.stockQuantity > 0 ? `${product.stockQuantity} ชิ้น` : 'สินค้าหมด'}
          </p>
        </div>
      </div>
    </div>
  );
}
```

## 4. เทียบกับวิธีเดิม (useEffect vs TanStack Query)

```tsx
// ❌ วิธีเดิม: 35+ บรรทัด จัดการสถานะด้วยตนเอง ไม่มีแคช ไม่มี auto-retry
export function LegacyProductDetails({ id }: { id: string }) {
  const [data, setData] = useState<Product | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let isCancelled = false;
    setLoading(true);
    setError(null);

    fetch(`/api/products/${id}`)
      .then((res) => {
        if (!res.ok) throw new Error('Failed');
        return res.json();
      })
      .then((resData) => {
        if (!isCancelled) setData(resData);
      })
      .catch((err) => {
        if (!isCancelled) setError(err.message);
      })
      .finally(() => {
        if (!isCancelled) setLoading(false);
      });

    return () => { isCancelled = true; };
  }, [id]);

  if (loading) return <div>Loading...</div>;
  if (error) return <div>{error}</div>;
  return <div>{data?.name}</div>;
}
```

```tsx
// ✅ TanStack Query v5: 8 บรรทัด มีแคช มี background revalidation และ retry อัตโนมัติ
export function ModernProductDetails({ id }: { id: string }) {
  const { data, isPending, isError, error } = useQuery({
    queryKey: ['products', 'detail', id],
    queryFn: () => fetchProductById(id),
  });

  if (isPending) return <ProductSkeleton />;
  if (isError) return <ErrorMessage message={error.message} />;
  return <ProductCard product={data} />;
}
```

## 5. ผิด vs ถูก

### แบบที่ผิด ❌: ใช้ `isFetching` สั่งแสดง Full Page Spinner ทำให้จอกระพริบเวลาสลับแท็บ

```tsx
// ❌ ผิด: ทุกครั้งที่ผู้ใช้สลับหน้าต่างกลับมา isFetching จะเป็น true ชั่วขณะ
// ทำให้หน้าจอผู้ใช้เด้งกลับไปเป็น Loading Spinner ทั้งๆ ที่มีข้อมูลเก่าอยู่แล้ว!
export function BadComponent({ productId }: { productId: string }) {
  const { data, isFetching } = useQuery({
    queryKey: ['products', productId],
    queryFn: () => fetchProductById(productId),
  });

  if (isFetching) {
    return <FullScreenSpinner />; // ❌ UX พัง: กระพริบทุกครั้งที่มี Background Sync
  }

  return <div>{data?.name}</div>;
}
```

### แบบที่ถูก ✅: ใช้ `isPending` สำหรับ Loading แรกเริ่ม และใช้ `isFetching` เป็น Subtle Indicator

```tsx
// ✅ ถูกต้อง: แสดง Skeleton เฉพาะตอนที่ยังไม่มีข้อมูลในแคช (isPending)
// หากมีข้อมูลแล้วแต่กำลังซิงค์เบื้องหลัง ให้แสดงหน้าจอเดิมพร้อมป้ายเล็กๆ
export function GoodComponent({ productId }: { productId: string }) {
  const { data, isPending, isFetching } = useQuery({
    queryKey: ['products', productId],
    queryFn: () => fetchProductById(productId),
  });

  if (isPending) {
    return <FullScreenSkeleton />;
  }

  return (
    <div>
      {isFetching && <SyncingProgressBar />}
      <div>{data.name}</div>
    </div>
  );
}
```

## 6. ควรใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่

### ควรใช้ `useQuery` เมื่อ:
- ต้องการดึงข้อมูลแบบ Read-only (GET request)
- ต้องการให้ข้อมูลซิงค์กับเซิร์ฟเวอร์สม่ำเสมอ
- ต้องการแคชข้อมูลข้ามหน้า หรือแชร์ข้อมูลข้ามหลายคอมโพเนนต์

### ไม่ควรใช้ `useQuery` เมื่อ:
- การส่งข้อมูลไปเปลี่ยนแปลงเซิร์ฟเวอร์ เช่น Create, Update, Delete (ให้ใช้ **`useMutation`**)
- การส่ง Request แบบ One-off ที่ต้องการเรียกตามการคลิกปุ่มของผู้ใช้เท่านั้นโดยไม่ผูกกับวงจรชีวิตของคอมโพเนนต์ (พิจารณาใช้ Server Action หรือ `mutate`)

## 7. คำถามสัมภาษณ์งาน (Interview Questions)

### Q1: ใน TanStack Query v5 อะไรคือความแตกต่างระหว่าง `isPending` กับ `isFetching` และในแง่ของ UX ควรนำไปใช้ต่างกันอย่างไร?
**แนวทางตอบ**:
- `isPending` คือสถานะที่บอกว่า **"ในแคชยังไม่มีข้อมูลเลย"** มักเกิดขึ้นตอน Mount คอมโพเนนต์ครั้งแรกสุด ควรนำไปใช้แสดง UI แทนที่ เช่น **Skeleton Loader** หรือ Loading Spinner ขนาดใหญ่
- `isFetching` คือสถานะที่บอกว่า **"กำลังมี Request วิ่งอยู่บนเครือข่าย"** ซึ่งจะเกิดขึ้นทั้งตอนโหลดครั้งแรก และตอนที่แอปทำการ Revalidate เบื้องหลัง (เช่น เมื่อสลับแท็บกลับมา หรือหมด `staleTime`) ในจังหวะ Revalidate ข้อมูลเก่ายังมีอยู่ในแคช เราไม่ควรแสดง Full Screen Spinner เพราะจะทำให้หน้าจอกระพริบ แต่ควรแสดง **Subtle Indicator** (เช่น ไอคอนหมุนเล็กๆ หรือแถบโหลดด้านบน) เพื่อให้ผู้ใช้ยังคงอ่านเนื้อหาเดิมได้ต่อเนื่อง

### Q2: ทำไมใน TanStack Query v5 ถึงตัด Overloads ที่รับ Parameter หลายตัว เช่น `useQuery(key, fn, options)` ออก และเหลือเพียง Object Syntax รูปแบบเดียว?
**แนวทางตอบ**:
1. **Type Safety**: การใช้ Object Syntax ช่วยให้ TypeScript สามารถทำ Type Inference ได้แม่นยำ 100% โดยไม่มีข้อจำกัดของการจำกัดรูปแบบ Function Overloads
2. **ขยาย Options ในอนาคตได้ง่าย**: หากต้องการเพิ่ม Parameter ใหม่ สามารถเพิ่ม Key ใน Object ได้ทันทีโดยไม่กระทบลำดับของ Argument
3. **ลด Bundle Size**: ไม่ต้องมีโค้ด Runtime ตรวจสอบชนิดของ Argument ว่าเป็น String, Array หรือ Function ในไลบรารี
